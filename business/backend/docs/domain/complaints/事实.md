# 商户投诉管理事实源

Identity 的 fulfillment capability 是店铺投诉工单的唯一事实源。菜单在商户后台「商城管理 / 投诉管理」。Trade 拥有订单资金，Catalog 拥有商品，Live 拥有房间；本表只保存对它们的稳定引用，不复制对方事实。

## 旧系统到当前模型的逐项对照

| 旧表/接口字段 | 旧语义证据 | 当前字段 | 迁移规则 |
|---|---|---|---|
| 旧接口 `GET /commercial/complaint/list` | 本店投诉分页 | `GET /merch/identity/complaints` | 不保留 `/commercial/*` 别名 |
| 旧接口 `GET /commercial/complaint/detail/{id}` | 打开一条投诉 | `GET /merch/identity/complaints/{complaintId}` | path 参数 `{complaintId}` |
| 旧接口 `POST /commercial/complaint/handle` | 处理/审核并写 `status`、`handle_note` | `POST /merch/identity/complaints/{complaintId}/review` | 旧 `handle` 映射为封闭方法词 `review` |
| `uid` | 投诉客户 | `customer_subject` | 全局 Identity subject；浏览器不得提交 `uid`/`appId`/`commercialId` |
| `target_type` / `target_id` | 被诉对象 | `target_type` / `target_id` | 封闭类型 + 非负整数引用；不建 Trade/Live/Catalog 外键 |
| `reason_code` | 原因码 | `reason_code` | trim 后 1–64 |
| `content` | 投诉正文 | `content` | trim 后 1–4000 |
| `status` | 处理状态 | `status` | 封闭枚举 `OPEN` / `ACCEPTED` / `REJECTED` |
| `handle_note` | 处理说明 | `handle_note` | 审核时必填 1–2000；未处理为空 |
| `page` / `perPage` | 分页 | `page` / `pageSize` | 默认 20，最大 100 |
| `appid` / `commercial_id` | 旧运行时隔离键 | 非运行时 | 只从 merch Module Session 读取 `merchant_id + shop_id` |

## 唯一事实源

- 投诉工单：`identity_complaint`，归属同一 `identity_shop` 行证明的 `merchant_id + shop_id`。
- 审核命令账本：`identity_complaint_command`，稳定 `commandKey` 幂等回执。
- `target_id` 只是对方模块主键引用；本模块不读取订单、售后、商品或直播库。
- 本切片商户页只列表、读取和审核。Shop 提交投诉是后续 shop surface，不走本菜单 HTTP。
- 关闭店铺后列表与审核视为范围不存在。工单不物理删除；审核进入 `ACCEPTED` 或 `REJECTED`。
- 不保存退款结果、库存回补或客服聊天记录。

商户后台菜单可见性仍受订阅权益约束。本地引导必须把 `identity.complaint.read` / `identity.complaint.manage` 加入商户 entitlement。

# 商户投诉管理对外契约

商户后台页面继续使用菜单路由 `/complaints`，经 Gateway 调用以下唯一主契约。范围只来自 merch Module Session 的 `merchantId + shopId`。

| 方法与路径 | 用途 | 幂等 |
|---|---|---|
| `GET /merch/identity/complaints` | 分页列出当前店铺投诉 | safe |
| `GET /merch/identity/complaints/{complaintId}` | 读取一条本店投诉 | safe |
| `POST /merch/identity/complaints/{complaintId}/review` | 审核本店 `OPEN` 投诉为 `ACCEPTED` 或 `REJECTED` | idempotent |

列表/详情要求 `identity.complaint.read`。审核要求 `identity.complaint.manage`。

响应 camelCase：`id`、`customerSubject`、`targetType`、`targetId`、`reasonCode`、`content`、`status`、`handleNote`、`version`、`createdAt`、`updatedAt`、`handledAt`。不返回 `merchantId`/`shopId`。审核响应另含 `replayed`。

查询参数：`customerSubject`、`status`、`targetType`、`page`、`pageSize`。

旧路径 `/commercial/complaint/*` 不再提供。浏览器不得提交 `appId`/`commercialId`/`uid` 或店铺 ID。本页不提供创建接口；Shop 提交不在本契约。

## 事件

本切片不发布 Outbox。后续若审核要触发 Trade 退款，必须走 Trade 公开幂等命令，不得直写订单库。

## 菜单与权益

Manifest Contribution `identity.merch.complaints` 开放 `/merch/identity/complaints` 的 GET 与 POST。菜单是否出现取决于商户套餐是否包含 `identity.complaint.read`。

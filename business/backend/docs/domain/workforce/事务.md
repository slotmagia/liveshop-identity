# 商户员工与主播事务与失败窗口

## 创建

1. 规范化姓名、账号、岗位、店铺、角色和幂等键。
2. 开启 Identity MySQL 事务并预约 `provision_member` 幂等行。
3. 锁定商户授权域，校验角色 ⊆ 权益。
4. 插入主体、成员、组织单元、店铺关系、凭据和 grant。
5. 授权域 revision +1，写 `identity.workforce.changed` Outbox，提交。

## 编辑

1. 预约 `update_member` 幂等行。
2. 按 `merchant_id + subject` 锁定未撤销 STAFF/ANCHOR。
3. 校验主体版本与 access 版本。
4. 更新显示名；替换组织单元和店铺关系；整组替换 grant。
5. 若店铺或角色集合变化：access_version +1，撤销会话，授权域 revision +1。
6. 写 Outbox 后提交。

## 启停 / 重置密码 / 撤会话

沿用 `UserLifecycle` 既有命令账本。停用、重置密码与主动撤会话都在同一事务把 session 与 refresh token 收敛为 `REVOKED`。

## 失败与恢复

- 幂等行插入后业务失败：事务回滚，可安全重试。
- 提交结果未知：相同键重试；已提交则重放，未提交则重新执行。
- 并发编辑同一成员：行锁和期望版本使一个成功、另一个冲突。
- 角色管理页与用户管理页不共享写事务；用户页只引用已存在角色。

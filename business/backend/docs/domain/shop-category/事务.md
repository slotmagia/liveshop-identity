# 店铺品类事务与失败窗口

## 写入链路

1. 校验命令键、期望版本、稳定代码和字段范围。
2. 开启 Identity MySQL 事务。
3. 插入 `identity_shop_category_command`；撞键时锁定并核对请求摘要，完整命令直接重放结果。
4. 编辑、启停和退役先用 `SELECT ... FOR UPDATE` 锁定品类并核对旧版本、旧状态和稳定代码。
5. 使用带版本和非退役前置条件的条件更新推进状态与版本。
6. 从数据库读取规范结果和实时店铺引用数。
7. 将响应与版本写入命令账本并提交事务。

## 失败与恢复

- 命令账本插入后业务写入失败：事务回滚，不能留下未完成命令。
- 业务写入成功但账本完成失败：事务整体回滚，重试仍可从原状态执行。
- 数据库提交结果未知：调用方用相同 `commandKey` 重试；已提交则重放，未提交则重新执行。
- 两个命令并发更新同一版本：行锁和条件更新使一个成功，另一个返回版本冲突；页面刷新后收敛。
- 相同命令重复投递：只产生一次状态变化和一次版本推进。
- 品类已被店铺引用后退役：只把目录行推进到 `RETIRED`；外键和保留行保证店铺引用不悬空。
- 进程在任意事务步骤崩溃：MySQL 回滚未提交事务；不依赖定时任务修复普通失败。

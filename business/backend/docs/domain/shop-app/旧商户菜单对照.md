# 商户后台「应用」迁移对照

## 旧页面与接口证据

- 菜单：`menu.settings_apps`，路由 `/settings/apps`。
- 旧前端：`woklive-merchant/src/views/business/settings/module.tsx`（`AppsPage`）。
- 旧接口：
  - `GET /commercial/settings/apps`
  - `POST /commercial/settings/apps/create`（`name`、`scopes`）
  - `POST /commercial/settings/apps/rotate-secret`（`id`）
  - `POST /commercial/settings/apps/toggle`（`id`、`enabled`）
- 旧表：`merchant_private_app`，范围是 `appid + commercial_id`，并把 `platform_status` 存在应用行上。轮换和启用要求平台状态为 `active`。明文密钥只在创建/轮换响应出现。
- 旧页说明：仅支持当前商户私有应用，不提供公开应用市场；应用授权与 Webhook 尚未接入。

## 字段映射

| 旧字段 / 行为 | 目标字段 / 行为 | 迁移规则 |
|---|---|---|
| `appid + commercial_id` | `merchant_id + shop_id` | 运行时不再使用应用/商业隔离 ID。 |
| `name` / `client_id` / `secret_hint` | 同名 | 密钥算法与尾号规则保持。 |
| 自由 `scopes` 字符串 | 封闭范围目录 | 旧默认 `orders:read,products:read` 仍可选；未知范围拒绝。 |
| `merchant_status` 小写 | `ACTIVE` / `DISABLED` | 列表与启停语义不变。 |
| 行上 `platform_status` | `identity_merchant_capability.module='apps'` | 不把平台状态复制到应用行；缺行视为 active。 |
| 单接口 toggle | `/enable` 与 `/disable` | 符合现行命令动词；停用在平台受限时仍允许。 |
| `rotate-secret` | `/reset` | 使用封闭方法词 `reset`；页面文案仍为轮换密钥。 |
| 无命令键 / 无乐观锁 | `commandKey` + `version` | 所有写命令可安全重试。 |
| 轮换需 step-up | 确认框 + 后续统一 step-up | 不在本 capability 自造第二套凭证。 |

## 页面迁移结果

- 菜单目录、名称和 `/settings/apps` 保持不变。
- 查询卡选择店铺和商户状态；数据卡列出名称、`client_id`、范围、密钥尾号、商户状态、平台叠加层和时间。
- 刷新、新建在数据卡工具栏；复制标识、轮换、启停在行内。表单和确认使用 `hostFormModal()`；范围使用 `checkbox-tree`。
- 无 `identity.app.manage` 时隐藏写按钮。平台受限时仍可停用，不能创建、轮换或启用。

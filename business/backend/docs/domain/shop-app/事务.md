# 店铺私有应用事务与失败窗口

## 写入链路

1. 规范化命令键、店铺范围、名称、范围目录和期望版本。
2. 开启 Identity MySQL 事务。
3. 插入 `identity_shop_app_command`；撞键时锁定并核对请求摘要，完整命令直接重放。
4. `SELECT ... FOR UPDATE` 锁定未关闭的 `identity_shop`。
5. 创建、轮换、启用时读取 `identity_merchant_capability`（`module='apps'`）`FOR UPDATE`。无行视为 `active`；非 `active` 拒绝。
6. 创建插入 `ACTIVE` 行；轮换更新散列/尾号并推进版本；启停校验旧状态后推进版本。
7. 同事务写入 `identity.shop.app.changed` Outbox（不含明文密钥），把规范结果（创建/轮换含明文密钥）写入命令账本后提交。

## 失败与恢复

- 命令账本插入后业务写入失败：事务回滚，不留下未完成命令或半截密钥。
- 数据库提交结果未知：调用方用相同 `commandKey` 重试；已提交则重放，未提交则重新执行。
- 两个写命令并发：行锁和 `expectedVersion` 使一个成功，另一个返回冲突。
- 认证级 step-up 仍由 Identity 会话能力统一建设；本页轮换用确认框表达高风险，不自造第二套 token 或 header。
- 进程在任意步骤崩溃：MySQL 回滚未提交事务；不依赖定时任务修复。

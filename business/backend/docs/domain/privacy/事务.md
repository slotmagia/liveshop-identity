# 店铺客户隐私事务与失败窗口

## 写入链路

1. merch 逻辑从 Module Session 读取 `merchant_id + shop_id`；缺失即拒绝，不接受请求体范围。
2. 读取 `module=privacy` 平台叠加层；非 `active` 立即拒绝，不开启隐私写事务。
3. 规范化 `commandKey`、同意开关、保留天数和邮箱。
4. 开启 Identity MySQL 事务（`REPEATABLE READ`）。
5. 插入 `identity_shop_privacy_command`；撞键时锁定并核对请求摘要，完整命令直接重放结果。
6. 锁定未关闭店铺行；关闭或缺失则失败。
7. 锁定现有隐私行（若有）并核对 `expectedVersion`；缺行只接受 `0`。
8. 插入版本 `1` 或条件更新并 `version+1`。
9. 同事务写入 `identity.shop.privacy.changed` Outbox，并将规范结果写入命令账本后提交。

## 失败与恢复

- 叠加层拒绝发生在写事务外，不留下命令账本。
- 命令账本插入后业务写入失败：事务回滚，不能留下未完成命令。
- 业务写入成功但账本或 Outbox 失败：事务整体回滚，重试仍可从原状态执行。
- 数据库提交结果未知：调用方用相同 `commandKey` 重试；已提交则重放，未提交则重新执行。
- 两个命令并发更新同一版本：行锁和条件更新使一个成功，另一个返回版本冲突。
- 进程在任意事务步骤崩溃：MySQL 回滚未提交事务；不依赖定时任务修复普通失败。

# Identity 业务不变量

| 编号 | 不变量 | 作用范围 | 保持机制 |
|---|---|---|---|
| ID-INV-1 | 每个 `subject` 全局只代表一个主体，realm 和 principal type 不可由请求改写 | 主体 | 全局主键、乐观锁；范围只来自成员关系 |
| ID-INV-2 | 一个活动登录凭据在其显式命名空间内只能解析到一个主体 | 凭据 | `namespace + kind + normalized_identifier` 唯一索引 |
| ID-INV-3 | `merchant_id` 与 `shop_id` 分别保持商户主体和店铺实体语义；`app_id`/`commercial_id` 不是运行时标识 | 全模块 | 独立列、独立约束、领域类型和迁移对照测试 |
| ID-INV-4 | 每个 `shop_id` 只对应一个未删除店铺，且该店铺只属于一个 merchant | 店铺 | 主键与 `merchant_id` 归属约束；商户、店铺关系在同库校验 |
| ID-INV-5 | 一个商户只有一个有效商户组织和一个有效所有者成员；平台只有一个有效平台组织 | 组织 | 类型唯一键、成员类型约束和事务内校验 |
| ID-INV-6 | 员工 `OPERATE` 店铺必须属于其商户且可多店；主播 `ANCHOR` 只绑定一个店铺且同店最多一个有效主播 | workforce/店铺 | 外键、有效唯一槽和事务内全量校验 |
| ID-INV-7 | 商户所有者的全部有效店铺范围从商户归属派生，员工命令不能停用或撤销所有者 | 所有者 | 受保护成员类型和命令前置条件 |
| ID-INV-8 | 停用主体、凭据、成员、商户或店铺不能建立新的有效登录或商业上下文 | 认证 | 认证和上下文解析同时校验全链路状态；默认拒绝 |
| ID-INV-9 | refresh token 只能成功轮换一次；重用 USED token 必须撤销整个 session family | 会话 | token/session 行锁、条件更新和同事务撤销 |
| ID-INV-10 | 修改密码、停用主体或成员时，活动 refresh token 与状态修改原子提交 | 账号/会话 | 同一 Identity 数据库事务 |
| ID-INV-11 | 重复的创建、分配、撤销命令不能产生重复主体、关系、会话或事件 | 所有写用例 | 稳定幂等键、唯一索引、请求摘要与既有结果返回 |
| ID-INV-12 | Identity 权威写入与通知 Platform 的事件不能永久分离 | 跨模块协作 | 业务行和 Outbox 同事务；消费者 Inbox 去重 |
| ID-INV-13 | 已激活但尚无 Identity role grant 的成员业务权限集合为空 | 授权 | 无 grant 即拒绝；成员创建与角色授予可在 Identity 同一用例中原子完成 |
| ID-INV-14 | Registry 权限投影不能成为权限定义或组织结构的第二写入入口 | 跨模块所有权 | 仅接受 Platform Registry 单调版本事件；Identity 只能引用活动权限码 |
| ID-INV-15 | 旧项目同一身份和商业上下文在迁移后得到相同业务归属结果 | 迁移 | 新旧语义对照、行数/校验和以及越权拒绝测试 |
| ID-INV-16 | Module Capability 必须来自同一次有效 Registry/权益/授权快照 | 签发 | Registry、Authorization、Entitlement revision 均非零；活动 Contribution、路由和权限定义缺一即拒绝 |
| ID-INV-17 | 商户角色只按真实 `merchant_id` 隔离；员工有效权限=`活动角色权限 ∩ 商户权益` | 商户授权 | 授权域主键与 entitlement projection 条件查询；禁止把已废弃的 `app_id` 写入角色域主键 |
| ID-INV-18 | 商户所有者不受员工角色限制，但仍受商户权益；员工/角色管理始终 owner-only | 商户授权 | owner 派生权益权限；业务用例再次校验 PrincipalType，误授管理权限也不能绕过 |
| ID-INV-19 | 角色 `code` 是稳定迁移键；总后台旧 `role_key` 一对一进入 role.code | 迁移 | 域内 role.code 唯一；禁止把 role_key 只保存为显示名或硬编码白名单 |
| ID-INV-20 | 已签 Module Capability 在授权/组织变化后最多继续有效配置 TTL（且不超过 5 分钟） | 收敛 | 短期令牌+版本 claims；新签发实时读取当前投影，旧令牌自然到期 |
| ID-INV-21 | 平台最后一个有效操作员以及持有活动 system role 的引导管理员不能被停用或重置凭据 | 平台用户 | 事务内锁定目标、统计活动操作员并检查 system role grant；不提供运行时 break-glass |
| ID-INV-22 | 用户状态或凭据变更只能作用于唯一的未撤销 workforce membership | 用户生命周期 | 写事务内校验 subject 只有一个非 REVOKED membership；歧义主体失败关闭，禁止全局状态误伤其它组织 |
| ID-INV-23 | 停用用户、重置凭据或主动下线时，session 与 refresh token 必须在同一事务收敛为 REVOKED | 会话 | 条件更新主体/成员/凭据后，同事务撤销对应会话和 refresh token 并写 Outbox |
| ID-INV-24 | 高风险写操作不能仅依赖尚未过期的 Module Capability | 即时撤权 | 写请求进入用例前，在同一只读快照复核活动 session/context、主体与组织版本、授权 revision、Registry revision，以及平台边界或商户权益 revision/新鲜度；任一变化失败关闭 |
| ID-INV-25 | 对外发布的店铺结算币种必须来自同一 `identity_shop` 行，且为大写 ISO 4217 三字母格式；币种不是 `ShopContext` 身份对的一部分 | 店铺只读契约 | 数据库 CHECK、仓储行映射与 biz 结果校验三层失败关闭；`ResolveShopContext.currency` 与 context/status/version 同一次查询返回 |
| ID-INV-26 | 游客只能由 Shop/Live surface 针对一个活动 shopCode 建立 CUSTOMER realm 的 `GUEST` 主体和完整店铺上下文，且不能取得登录专属操作 | 游客会话 | Identity 原子解析店铺并签发会话；Gateway 与模块同时校验 operation authentication 和 principal type |
| ID-INV-27 | 客服账号只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`，且同店铺 `(platform, account)` 唯一 | Customer Service | 事务内锁定店铺、独立维度列、唯一索引、版本条件更新和命令幂等账本 |
| ID-INV-28 | 店铺隐私文档只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；平台叠加层不得写入隐私表；受限时禁止保存 | shop privacy | 事务内锁定未关闭店铺、`shop_id` 唯一、版本条件更新、命令幂等账本；merch 逻辑读取 `module=privacy` 叠加层 |
| ID-INV-29 | 店铺政策只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；同店同类型最多一条 `PUBLISHED`；平台叠加层不得写入政策表 | shop policy | 事务内锁定未关闭店铺、`(shop_id, policy_type, version_no)` 唯一、发布归档、命令幂等账本；非 active 叠加层只阻止发布 |
| ID-INV-30 | 店铺私有应用只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；`client_id` 全局唯一；明文密钥不进列表；平台叠加层不得写入应用表 | shop app | 事务内锁定未关闭店铺、密钥单向散列、版本条件更新、命令幂等账本；非 active 叠加层阻止创建/轮换/启用 |
| ID-INV-31 | 商户自助改密只能作用于当前 Module Session 的 `subject`，必须核验旧密码，并在同一事务撤销其它活动会话而保留当前会话 | 账号安全 | 请求不得携带 subject/credentialId/sessionId；bcrypt 核验失败回滚；撤销谓词排除当前 session_id |
| ID-INV-32 | 设备登录只能列出和撤销当前 Module Capability subject 自己的未过期会话；请求不得携带他人 subject | 账号会话 | 路径固定 `/merch/identity/account/sessions`；自助成员校验含 OWNER；仓储按 `session_id + subject` 锁定；过期行不进列表 |
| ID-INV-33 | 店铺风控事件只能列出同一 `identity_shop` 行证明的 `merchant_id + shop_id`；事件只追加；当前决策不得写回历史事件行 | risk events | 路径固定 `/merch/identity/risk-events`；范围只来自 merch Session；关闭店铺视为不存在；`room_id` 无 Live 外键 |
| ID-INV-34 | 店铺投诉只能列出、读取和审核同一 `identity_shop` 行证明的 `merchant_id + shop_id`；`OPEN` 只能转入 `ACCEPTED`/`REJECTED`；审核必须带 `commandKey` 与 `expectedVersion` | complaints | 路径固定 `/merch/identity/complaints`；范围只来自 merch Session；关闭店铺视为不存在；`target_id` 无对方模块外键 |
| ID-INV-34 | 店铺自定义域名只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；未删除 host 全局唯一；每店每场景最多一个未删除主域名；仅 `VERIFIED` 可激活；平台叠加层不得写入域名表 | shop domain | 事务内锁定未关闭店铺、生成列唯一槽、版本条件更新、命令幂等账本；非 active 叠加层阻止创建/校验/设主；删除始终允许；直播页场景固定 `LIVE` |
| ID-INV-35 | 店铺配送规则与发货预设只能绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；同店未退役预设最多一个默认；平台叠加层不得写入配送表；退役为终态 | shipping-delivery | 事务内锁定未关闭店铺、版本条件更新、命令幂等账本；非 active 叠加层阻止全部写入；`product_id` 无 Catalog 外键 |
| ID-INV-35 | 店铺售后只能列出、读取、审核和确认退货同一 `identity_shop` 行证明的 `merchant_id + shop_id`；`PENDING` 只能转入 `APPROVED`/`REJECTED`；退货收货不回补 Catalog、审核通过不执行 Trade 退款；写命令必须带 `commandKey` 与 `expectedVersion` | aftersales | 路径固定 `/merch/identity/aftersales`；范围只来自 merch Session；关闭店铺视为不存在；`order_id`/`sku_id` 无对方模块外键 |
| ID-INV-36 | 店铺发货单只能列出、读取、发货、追加轨迹和确认收货同一 `identity_shop` 行证明的 `merchant_id + shop_id`；同店同订单唯一；`SHIPPED` 只能追加轨迹或 `close` 为 `DELIVERED`；写命令必须带 `commandKey`，轨迹与确认收货还要 `expectedVersion` | shipments | 路径固定 `/merch/identity/shipments`；范围只来自 merch Session；关闭店铺视为不存在；`order_id` 无 Trade 外键 |
| ID-INV-37 | 登录验证码挑战只能绑定一个活动店铺；明文验证码不得持久化；`Dispatch` 必须在挑战事务提交之后；请求渠道非 `SENT` 时对用户失败且不删除挑战；Platform 不得知道验证码是否正确 | auth OTP | 散列入库；`deliveryKey=identity.auth.otp.requested:<challengeId>`；SYNC 客户端只看请求渠道状态 |
| ID-INV-38 | 游客登录升级必须在同一 Identity 事务完成凭据与会话归属；禁止只把 `GUEST` 改成 `CUSTOMER`；已核验挑战只能兑现一次 | 游客升级 | `/auth/login` 锁定 `CONSUMED` 挑战；无同店凭据时升格当前游客主体；已有凭据则签发到该顾客并撤销游客会话；Catalog 购物车等外模块经 `identity.guest.upgraded` 后续归属 |

所有状态写入必须携带 `expected_version` 或预期旧状态。数据库约束负责最后防线，领域错误负责向调用方表达冲突原因。

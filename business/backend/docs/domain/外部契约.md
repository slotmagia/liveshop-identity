# Identity 外部契约

## 浏览器认证边界

`/auth/*` 是 Gateway 显式白名单代理到 Identity 的系统边界，不属于 Module Manifest，也不要求 Module Capability；它必须实施凭据防枚举、限流、CSRF/Cookie 和审计保护。

| 操作 | 鉴权 | 幂等 | 说明 |
|---|---|---|---|
| `POST /auth/login` | 凭据 | 否 | `{realm,username,password,shopCode?}`；CUSTOMER 必须提供 shopCode 定位 SHOP 命名空间，MERCHANT/PLATFORM 不需要；GUEST 禁止密码登录 |
| `POST /auth/guest` | Shop/Live surface + shopCode | 否 | 只接受 `{shopCode}`；原子创建 CUSTOMER realm 的 GUEST 主体、店铺绑定会话和 refresh cookie；Host 应先 refresh，只有无可恢复会话时才调用 |
| `POST /auth/refresh` | refresh cookie | 单次轮换 | USED token 重用撤销 session family |
| `POST /auth/logout` | refresh cookie | 是 | 撤销当前 session |
| `POST /auth/context/switch` | Access Identity | 是 | 验证成员/店铺关系并签发新上下文，不信任裸 header |
| `GET /auth/me` | Access Identity | safe | 返回认证主体和已验证商业上下文，不计算角色权限 |

`POST /runtime/v1/module-sessions` 验证 Identity Access Identity，在同一有效投影快照计算授权并签发 contribution-scoped Module Capability。响应使用 Host 契约的 `token` 与 `tenant`（`merchant_id + shop_id`）；HTTP 资源名固定，但 token 线语义是 `LIVESHOP-MODULE-CAPABILITY`，不得增加兼容签发路由。claims 不再携带 `appId`/`commercialId`。

## 页面 HTTP（经 Gateway）

Admin 与 Merch contribution 使用 Identity 签发的 Module Capability。

| 路径族 | Surface | 事实范围 | 权限前缀 |
|---|---|---|---|
| `/admin/identity/users`、`/admin/identity/sessions` | admin | 平台操作员生命周期、凭据和会话管理 | `identity.user.manage`、`identity.session.manage` |
| `/admin/identity/merchants` | admin | 商户开户、状态、关闭、重置密码、套餐指派，以及支付/短信/流媒体编排 | `identity.merchant.manage` |
| `/admin/identity/organizations` | admin | 平台组织和受控商户组织治理 | `identity.organization.*` |
| `/merch/identity/profile` | merch | 当前商户自服务资料；账号/公司名/状态只读 | `identity.profile.manage` |
| `/merch/identity/account` | merch | 当前登录身份、可访问店铺、套餐权益与组织计数；不含他人凭据或写命令 | `identity.organization.read` |
| `/merch/identity/account/sessions` | merch | 当前登录主体自己的设备会话列表与自助撤销 | `identity.organization.read` |
| `/merch/identity/account/security`、`/merch/identity/account/credentials` | merch | 当前登录凭据快照；旧密码 step-up 后自助改密并撤销其它会话 | `identity.organization.read` |
| `/merch/identity/directory`、`/members` | merch | 当前商户员工、主播、凭据和店铺范围 | `identity.staff.*` |
| `/merch/identity/organization-units` | merch | 当前商户组织结构 | `identity.organization.*` |
| `/merch/identity/shops` | merch | 店铺及员工店铺范围 | `identity.shop.*` |
| `/merch/identity/privacy` | merch | 当前店铺顾客隐私文档；平台叠加层只读 | `identity.privacy.manage` |
| `/merch/identity/policies`、`/merch/identity/policies/shops` | merch | 当前商户店铺政策版本；平台叠加层只读 | `identity.policy.read`、`identity.policy.manage` |
| `/merch/identity/apps`、`/merch/identity/apps/shops`、`/merch/identity/apps/scopes` | merch | 当前商户店铺私有应用凭据；平台叠加层只读 | `identity.app.read`、`identity.app.manage` |
| `/merch/identity/risk-events` | merch | 当前店铺游客风险事件只读列表；JOIN 当前分数/等级/状态 | `identity.risk.read` |
| `/merch/identity/subscription`、`/merch/identity/subscription/plans`、`/merch/identity/subscription/pay-methods`、`/merch/identity/subscription/orders` | merch | 当前商户套餐目录、指派、购买订单；付款结果引用 Trade | `identity.subscription.read`、`identity.subscription.purchase` |
| `/merch/identity/anchors` | merch | 主播身份和固定店铺关系 | `identity.anchor.*` |
| `/merch/identity/sessions` | merch | 员工登录设备与强制下线（他人会话，owner + `identity.session.manage`） | `identity.session.manage` |
| `/admin/identity/customer-accounts[/{accountID}]` | admin | 维护外部客服账号；列表可按商户/店铺筛选，写入必须带明确范围 | `identity.customer-account.manage` |
| `/admin/identity/merchant-governance` | admin | 按权威商户和店铺范围维护商户能力平台叠加层与干预审计 | `identity.merchant-governance.manage` |

Manifest 权限定义由 Platform Registry 激活目录拥有；Identity 只消费投影，并拥有角色授予和运行时执行。

页面写操作除校验 `requiredPermissions` 外，还实时校验 Module Capability 中的 session/context、Identity、Organization、Authorization、Registry 与 Entitlement revisions。旧 token 即使仍在 5 分钟 TTL 内也不能执行高风险写入；调用方应重新请求 Module Capability，而不是重试旧 token。

## gRPC

| 方法 | 调用方 | deadline | 幂等 | 说明 |
|---|---|---:|---|---|
| `ResolvePrincipalContext` | 获准的 Platform Audit/业务工作负载 | 300ms | 是 | 返回主体状态、principal type、成员、组织、当前/可用店铺和版本；非 ACTIVE 失败关闭；不得据此在 Platform 重建 IAM |
| `ResolveShopContext` | 获准的 Gateway 边缘适配器、Platform Audit 或业务模块 | 300ms | 是 | 按 `shop_id` 解析权威 `merchant_id + shop_id`，并以响应顶层 `currency` 返回同一店铺行的大写 ISO 4217 结算币种；币种不进入 `ShopContext`。缺失、大小写错误、长度错误或持久化身份事实非法时返回失败，不得返回空币种或由调用方默认 USD/CNY |
| `GetShop` | 业务模块 | 300ms | 是 | 获取店铺事实；调用方不得复制为可写事实 |
| `ValidateSelectedContext` | 获准的 Gateway/业务工作负载 | 300ms | 是 | 验证主体仍可进入指定组织/商户/店铺上下文 |
| `GetOrganizationSubtree` | 获准的审计/业务工作负载 | 300ms | 是 | 返回有效组织单元 ID；Identity 仍是组织与 DataScope 的唯一拥有者 |
| `BatchGetSubjects` | Platform Audit、一次性业务迁移或业务展示工作负载 | 500ms | 是 | 返回主体展示信息及只读 `legacy_uid` 迁移映射，不返回凭据和 secret hash；调用方不得用 `legacy_uid` 创建新交易 |
| `ResolveLegacySubjects` | 一次性业务数据迁移工作负载 | 500ms | 是 | 按明确 realm 和至多 200 个旧 UID 返回唯一 Subject 映射；缺失项不伪造，迁移方必须把缺失或重复输入作为阻塞异常 |

gRPC 使用 mTLS + workload identity。调用超时不得被解释为主体有效；授权路径默认拒绝，普通展示路径可返回稍后重试。

当前服务端配置仍只有单值 `grpc.platform_spiffe_id` allowlist；因此现状只有该 Platform workload 能实际调用 Directory RPC。Gateway 或业务模块接入前必须把它直接演进成逐 workload、逐方法最小权限策略并补契约测试，不能通过共享 Platform 证书或放宽为任意受信 CA 客户端来绕过。

## 事件

| 事件 | 触发时机 | 消费者 | 顺序要求 |
|---|---|---|---|
| `identity.subject.changed` | 主体/凭据状态提交 | 显式登记的审计或业务消费者 | 按 subject version 有序 |
| `identity.credential.changed` | 管理员重置或商户自助改密提交 | 显式登记的审计消费者 | 按 credential version 有序 |
| `identity.organization.changed` | 平台/商户组织单元或成员提交 | 显式登记的审计或业务消费者 | 按 organization version 有序 |
| `identity.workforce.changed` | 人员状态、组织/店铺范围提交 | 显式登记的业务消费者 | 按 member access version 有序 |
| `identity.shop.changed` | 店铺及商业映射提交 | 显式登记的 Gateway 边缘投影或业务消费者 | 按 shop version 有序 |
| `identity.merchant_capability.changed` | 商户能力平台叠加层干预提交 | Platform Audit 及显式登记的业务消费者 | 按 capability version 有序 |
| `identity.shop.privacy.changed` | 店铺隐私文档首次保存或后续版本推进 | 显式登记的 Live analytics 等消费者 | 按 privacy version 有序 |
| `identity.shop.app.changed` | 店铺私有应用创建、轮换或启停提交 | 显式登记的审计消费者 | 按 app version 有序；载荷不含明文密钥 |

事件采用至少一次语义。每个显式登记的消费者必须以 `event_id` 去重，并以 aggregate version 防止乱序覆盖；Platform 不得通过消费这些事件重建角色、grant、DataScope 或有效授权副本。

当前主实现已把用户与组织变更原子写入 `identity_outbox`，但仓库内尚无生产 publisher/transport。完成发布器与消费者登记前，这些行只是待发布契约，消费者必须使用已发布的 mTLS gRPC 查询，不能假定事件已经送达；发布器落地时必须保留至少一次、可重放和消费者 Inbox 去重语义。

## 契约演进

这是迁移中的新唯一主契约，不建立 `identity-tenant`、`merchant identity` 或 Platform Identity 的长期兼容入口。仓库内调用方同步迁移；真正存在不可修改的外部消费者时再单独评审版本策略。

# 店铺查询事务与失败窗口

总后台店铺页分两次执行只读查询：先读取商户目录，再按选中的 `merchant_id` 读取店铺目录。每次查询使用请求 context；没有跨两次请求的写入事务。

- 商户在两次请求之间关闭：店铺查询仍按真实 `merchant_id` 隔离，但后续刷新会从商户目录移除该商户。
- 店铺在列表请求期间变更：单次 SQL 语句返回数据库一致结果；页面刷新后收敛到新状态和版本。
- 数据库不可达或查询失败：返回不可用，不返回静态假数据、缓存旧列表或其他商户数据。
- `merchant_id <= 0`：在进入仓储前拒绝，不执行无范围全表店铺查询。
- Platform 公共域名配置不可读：不构造猜测 URL；店铺短码和子域名标识仍按 Identity 事实返回。
- 通用店铺设置读取当前会话店铺：一次按 `merchant_id + shop_id` 查询非关闭行。会话缺少店铺或店铺已关闭时拒绝，不回退到该商户第一家店。

# 商户后台写入事务

每条写命令使用稳定 `commandKey`、同库命令账本和 `READ COMMITTED` 事务。

- 新建：锁商户行（拒绝 `CLOSED`）→ 校验启用品类 → 分配 `shop_id` 与短码 → 插入店铺 → 为当前 OWNER 写入 `OPERATE` 店铺关系 → 完成命令账本。
- 编辑名称/子域名：锁店铺行，校验归属、版本和非关闭状态；子域名冲突返回冲突。
- 启停：校验期望版本和当前状态；已处于目标状态时不推进版本，但命令账本仍记录规范结果。
- 关闭：校验并非该商户最后一家非关闭店铺，然后写入 `CLOSED` 与 `closed_at`。
- 相同 `commandKey` 且摘要相同：重放第一次结果。摘要不同：幂等冲突，不覆盖。
- 并发版本不匹配：返回冲突并回滚。
- 失败窗口：事务回滚后不留下半成品店铺或未完成命令账本；调用方用同一 `commandKey` 重试。

# 店铺不变量

1. `merchant_id` 和 `shop_id` 始终是两个不同业务概念；页面、接口和查询条件不得互相替代。`app_id`/`commercial_id` 不是运行时标识。
2. 每条店铺记录只能归属一个真实商户；按商户下钻不能返回其他商户的店铺。商户后台写命令必须使用会话中的 `merchant_id`，浏览器不得改写归属。
3. `shop_id`、店铺 `code`、非空 `subdomain` 分别保持唯一。
4. `CLOSED` 商户和店铺不进入当前管理目录；`DISABLED` 仍可见，以保留旧页面“含停用记录”的可观察行为。
5. 店铺状态只从 Identity 权威行读取；页面不得根据链接是否存在推断启停状态。
6. 总后台只读接口不得修改商户、店铺、组织、授权、会话或 Platform 配置，不产生 Outbox 事件。
7. 店铺客户隐私文档按 `shop_id` 唯一，且必须与同一 `identity_shop` 行的 `merchant_id` 一致；平台 `privacy` 叠加层不得写入该表。
8. 店铺政策版本按 `(shop_id, policy_type, version_no)` 唯一，且必须与同一 `identity_shop` 行的 `merchant_id` 一致；平台 `policies` 叠加层不得写入该表。
9. 店铺私有应用必须与同一 `identity_shop` 行的 `merchant_id` 一致；`client_id` 全局唯一；平台 `apps` 叠加层不得写入该表。
10. 经营品类一旦写入不可改；空值表示未选择。创建时若提供代码，必须命中当前 `ACTIVE` 品类。
11. 币种和默认语言在创建时固化；商户后台编辑只改名称、子域名和启停状态。
12. 每个非关闭商户至少保留一家非关闭店铺。关闭最后一家非关闭店铺必须拒绝。
13. 关闭商户后不得再新建或启用店铺。`CLOSED` 店铺是终态。
14. 商户后台写命令仅 `MERCHANT_OWNER` 可执行；员工即使用有读权限也不能改店铺身份。
15. 通用店铺设置只读取会话 `shop_id` 对应的非关闭店铺；浏览器不得提交其他 `shop_id` 作为当前店。保存仍走店铺更新命令，短码、币种、语言和品类不可改。
16. 店铺自定义域名必须与同一 `identity_shop` 行的 `merchant_id` 一致；未删除 `host` 全局唯一；平台 `domains` 叠加层不得写入该表。

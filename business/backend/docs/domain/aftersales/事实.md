# 商户售后工单事实源

Identity 的 fulfillment capability 是店铺售后工单的唯一事实源。菜单在商户后台「履约营销 / 售后工单」。Trade 拥有订单与退款资金，Catalog 拥有库存；本表只保存对它们的稳定引用，不复制对方事实，也不在本切片执行退款或回补。

## 旧系统到当前模型的逐项对照

| 旧表/接口字段 | 旧语义证据 | 当前字段 | 迁移规则 |
|---|---|---|---|
| 旧接口 `GET /commercial/aftersale/list` | 本店售后分页 | `GET /merch/identity/aftersales` | 不保留 `/commercial/*` 别名 |
| 旧接口 `GET /commercial/aftersale/detail/{id}` | 打开一条工单 | `GET /merch/identity/aftersales/{aftersaleId}` | path 参数 `{aftersaleId}` |
| 旧接口 `POST /commercial/aftersale/review` | 审核；通过即编排 Trade 退款 | `POST /merch/identity/aftersales/{aftersaleId}/review` | 只写审核事实；不调用 Trade |
| 旧接口 `POST /commercial/aftersale/receive` | 确认退货并直改 Catalog 库存 | `POST /merch/identity/aftersales/{aftersaleId}/returns` | 旧 `receive` 映射为 `returns.create`；只推进退货状态 |
| `uid` | 申请客户 | `customer_subject` | 全局 Identity subject；浏览器不得提交 `uid` |
| `order_id` | 关联订单 | `order_id` | Trade 引用，无外键 |
| `pay_no` | 支付单号 | `payment_no` | Trade 引用；本切片不据此退款 |
| `type` | `refund_only` / `return_refund` | `REFUND_ONLY` / `RETURN_REFUND` | 大写封闭枚举 |
| `amount` | 申请/批准金额（最小货币单位） | `requested_amount` + `amount` | 审核通过可下调 `amount`，不得高于申请额 |
| `reason` | 申请原因 | `reason` | trim 后 1–255 |
| `status` | `pending` 等小写 | `PENDING` / `APPROVED` / `REJECTED` / `REFUNDED` / `CLOSED` | 本切片 merch 只写前三个 |
| `return_status` | `not_required` / `received` | `NOT_REQUIRED` / `PENDING` / `RECEIVED` | 仅退款固定 `NOT_REQUIRED` |
| `note` | 审核说明 | `handle_note` | 审核时必填 1–2000；未审为空 |
| `aftersale_item` | 行项目与收货数量 | `identity_aftersale_item` | 保存 sku 引用、数量、申请退款额与标题快照；不保存 restock 租户 |
| `page` / `per_page` | 分页 | `page` / `pageSize` | 默认 20，最大 100 |
| `appid` / `commercial_id` | 旧运行时隔离键 | 非运行时 | 只从 merch Module Session 读取 `merchant_id + shop_id` |

## 唯一事实源

- 售后工单：`identity_aftersale`，归属同一 `identity_shop` 行证明的 `merchant_id + shop_id`。
- 行项目：`identity_aftersale_item`，只服务本工单；`sku_id` 是 Catalog 引用。
- 命令账本：`identity_aftersale_command`，稳定 `commandKey` 幂等回执。
- 本切片商户页只列表、读取、审核和确认退货。Shop 申请、Trade 退款回写、Catalog 回补不在本菜单 HTTP。
- 关闭店铺后列表与写命令视为范围不存在。工单不物理删除。
- 不保存订单总额、币种、成交价或已退资金；那些归 Trade。

商户后台菜单可见性仍受订阅权益约束。本地引导必须把 `identity.aftersale.read` / `identity.aftersale.manage` 加入商户 entitlement。

# 旧商户后台「售后工单」迁移对照

## 旧页面与接口证据

- 页面入口：`src/views/business/aftersale`。
- 菜单：履约营销 / 售后工单，路由 `/aftersale`。
- 旧接口：`GET /commercial/aftersale/list`、`GET /commercial/aftersale/detail/{id}`、`POST /commercial/aftersale/review`、`POST /commercial/aftersale/receive`。
- 旧列表查询：`uid`、`status`、`page`、`per_page`。
- 旧审核：`id`、`approve`、`amount`、`note`；通过即同步调用 Trade 退款。
- 旧收货：`id`；要求已退款的退货单，并直改 `catalog_sku.stock`。
- 旧行为：筛选/分页；打开详情；审核通过/拒绝；确认退货。Shop 申请不在本页。

## 字段映射

| 旧字段 / 行为 | 目标字段 / 行为 | 迁移规则 |
|---|---|---|
| `appid` / `commercial_id` | `merchant_id + shop_id` | 只从 merch Module Session 读取。 |
| `uid` | `customerSubject` | Identity subject；列表筛选不再使用整数 uid。 |
| `approve` 布尔 | `status=APPROVED\|REJECTED` | 与投诉页一致，用封闭状态而不是布尔。 |
| `receive` | `returns.create` | 封闭方法词不含 `receive`；嵌套资源 `create`。 |
| `per_page` | `pageSize` | 默认 20，最大 100。 |
| 任意 `status` 字符串 | 大写封闭枚举 | 拒绝未登记状态。 |
| 同步退款 / 直改库存 | 不迁入本页 | Trade / Catalog 后续公开命令。 |
| 页面结构 | Host 查询卡 + 数据卡表格 + `hostFormModal` | 分页在数据卡 footer；失败用 `notify()`。 |

## 页面迁移结果

- 菜单目录、名称和 `/aftersale` 路由保持不变。
- Contribution 为 `identity.merch.aftersale`。
- 页面不提供静态假数据；空列表合法。
- 不迁移 Shop 申请、订单金额富化、Catalog 回补或 Trade 退款执行。

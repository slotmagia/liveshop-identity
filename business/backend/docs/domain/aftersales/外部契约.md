# 商户售后工单对外契约

商户后台页面继续使用菜单路由 `/aftersale`，经 Gateway 调用以下唯一主契约。范围只来自 merch Module Session 的 `merchantId + shopId`。

| 方法与路径 | 用途 | 幂等 |
|---|---|---|
| `GET /merch/identity/aftersales` | 分页列出当前店铺售后 | safe |
| `GET /merch/identity/aftersales/{aftersaleId}` | 读取一条本店售后（含行项目） | safe |
| `POST /merch/identity/aftersales/{aftersaleId}/review` | 审核本店 `PENDING` 售后为 `APPROVED` 或 `REJECTED` | idempotent |
| `POST /merch/identity/aftersales/{aftersaleId}/returns` | 确认退货收货，推进 `return_status=RECEIVED` | idempotent |

列表/详情要求 `identity.aftersale.read`。审核与确认退货要求 `identity.aftersale.manage`。

响应 camelCase：`id`、`customerSubject`、`orderId`、`paymentNo`、`type`、`requestedAmount`、`amount`、`reason`、`status`、`returnStatus`、`handleNote`、`items`、`version`、`createdAt`、`updatedAt`、`reviewedAt`、`receivedAt`。不返回 `merchantId`/`shopId`。写响应另含 `replayed`。

查询参数：`customerSubject`、`status`、`type`、`page`、`pageSize`。

旧路径 `/commercial/aftersale/*` 不再提供。浏览器不得提交 `appId`/`commercialId`/`uid` 或店铺 ID。本页不提供创建接口；Shop 申请不在本契约。

## 事件

本切片不发布 Outbox。后续若审核要触发 Trade 退款或收货要触发 Catalog 回补，必须走对方公开幂等命令，不得直写订单库或库存表。

## 菜单与权益

Manifest Contribution `identity.merch.aftersale` 开放 `/merch/identity/aftersales` 的 GET 与 POST。菜单是否出现取决于商户套餐是否包含 `identity.aftersale.read`。

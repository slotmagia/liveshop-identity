# Identity 状态机

## 主体、商户、店铺、组织和组织单元

这些聚合沿用旧项目的启用/停用语义，不在架构迁移中发明新的业务状态：

```text
ACTIVE ──disable──> DISABLED
DISABLED ──enable──> ACTIVE
ACTIVE|DISABLED ──close/delete──> CLOSED
```

| 转换 | 前置条件 | 副作用 | 幂等 |
|---|---|---|---|
| `ACTIVE → DISABLED` | 当前版本匹配 | 主体/员工停用时撤销活动 session；同事务写 Outbox | 重复请求返回既有状态 |
| `DISABLED → ACTIVE` | 当前版本匹配，所属商户和必要父实体有效 | 同事务写状态变更事件 | 重复请求返回既有状态 |
| `ACTIVE/DISABLED → CLOSED` | 当前版本匹配且满足删除规则 | 软删除并撤销活动 session；保留历史引用 | 重复关闭返回既有结果 |
| `CLOSED → *` | 不允许 | 无 | 返回状态冲突 |

平台操作员和商户员工的启停同时转换 subject 与 workforce：`ACTIVE/ACTIVE → DISABLED/SUSPENDED`、`DISABLED/SUSPENDED → ACTIVE/ACTIVE`。两行分别校验 `expected_identity_version` 与 `expected_access_version`；任一冲突则整个事务回滚。平台 system role 持有人和最后一个活动平台操作员不允许进入停用状态。商户 owner 不在员工生命周期命令目标集合内。

店铺进入 `DISABLED/CLOSED` 后，历史业务数据仍保留原 `commercial_id` 和 `shop_id`，但不能签发新的该店铺商业上下文。

## 订阅套餐与权限策略

```text
ACTIVE ──disable──> DISABLED ──enable──> ACTIVE
ACTIVE|DISABLED ──retire──> RETIRED
RETIRED ──任何命令──> 拒绝
```

- 套餐基本信息转换校验 `expectedVersion`；默认套餐不能停用或退役，必须先原子切换另一活动默认套餐。
- 新建套餐在同一事务生成空权限集合和显式不限额额度策略，策略 `policyRevision=1`。
- 权限配置不会改变套餐生命周期或基本信息 version，只在完整集合校验后递增 `policyRevision`。
- `RETIRED` 是套餐和策略共同终态；历史权限、额度与命令结果保留用于审计。

## Refresh Token

```text
ACTIVE ──rotate──> USED
ACTIVE ──logout/account-change/disable/self-revoke──> REVOKED
USED ──reuse-detected──> session REVOKED
```

- `ACTIVE → USED` 与新 token 插入必须处于同一事务。
- `USED` token 再次出现视为凭据泄露，撤销整个 session family。
- `USED`、`REVOKED` 都是终态，不能恢复为 `ACTIVE`。
- 商户自助改密把其它设备的 ACTIVE 会话/refresh 推进到 `REVOKED`，当前 Module Session 保持 `ACTIVE`。管理员重置他人凭据仍撤销该主体全部会话。

## 登录会话自助撤销

商户后台设备登录不新增会话状态。当前主体对自己的 `ACTIVE` 会话执行自助撤销后进入 `REVOKED`，原因 `SELF_REVOKED`。详细命令表见 [`account/状态机.md`](./account/状态机.md)。

## 登录验证码挑战

```text
PENDING ──verify──> CONSUMED
PENDING ──ttl / too-many-attempts──> EXPIRED
```

- 请求验证码先插入 `PENDING` 再 `Dispatch`。发送失败保持 `PENDING`，按 TTL 进入 `EXPIRED`。
- `CONSUMED` 与 `EXPIRED` 都是终态。核验成功不得改写游客 principal type。
- 详细字段见 [`auth/状态机.md`](./auth/状态机.md)。

## 游客会话

游客创建后主体为 `ACTIVE/GUEST`，会话和 refresh token 遵循与普通 CUSTOMER 相同的轮换、撤销和过期状态机。游客没有密码凭据，不能通过 `/auth/login` 重新认证；Host 先尝试 refresh 恢复同一主体，refresh 不可用时才创建新的游客主体。游客登录升级需要独立、原子的数据归属迁移用例，未完成迁移前不得仅改写 principal type。

## Workforce 成员

```text
ACTIVE ──suspend──> SUSPENDED ──enable──> ACTIVE
ACTIVE|SUSPENDED ──revoke──> REVOKED
```

- Identity 在一个事务内创建主体、凭据、成员和店铺关系，成功即为 `ACTIVE`；可在同一 Identity 用例中以稳定 operation ID 同步写入初始角色 grant。
- 新成员没有角色授权时业务权限集合为空；角色 grant 失败时整个组合创建回滚，不留下需要前端双写恢复的半成品。
- 店铺/组织范围替换在一个 Identity 事务内完成、递增 `access_version` 并撤销活动会话；不会进入等待外部确认的状态。
- `REVOKED` 是终态，保留历史主体和审计引用。
- 所有者成员不可通过员工管理命令 suspend/revoke。

## 组织成员和店铺关系

组织成员关系和 `identity_member_shop` 在成员聚合事务中全量校验后替换并递增 `access_version`。`OPERATE` 允许员工多店；`ANCHOR` 必须满足同一成员单店、同一店铺单有效主播。撤销关系不使历史事件失去可追溯性。

## 客服账号

客服账号状态为 `ACTIVE ↔ DISABLED`；两种状态都可按当前版本删除，删除后事实行不存在且为终态。详细字段与命令状态见 [`customer-service/状态机.md`](./customer-service/状态机.md)。

## 店铺政策

政策版本状态为 `DRAFT → PUBLISHED`，同类型新发布把旧发布版推进到 `ARCHIVED`。禁止就地编辑和删除。详细字段与命令状态见 [`shop-policy/状态机.md`](./shop-policy/状态机.md)。

## 店铺客户隐私

隐私文档没有独立业务状态枚举。缺行时 GET 返回 `version=0` 默认值；首次保存插入 `version=1`，后续保存推进版本。`restricted`/`suspended` 平台叠加层禁止保存。详细命令表见 [`privacy/状态机.md`](./privacy/状态机.md)。

## 店铺私有应用

私有应用状态为 `ACTIVE ↔ DISABLED`。创建进入 `ACTIVE`；轮换密钥不改状态但使旧密钥失效。不提供物理删除。详细命令表见 [`shop-app/状态机.md`](./shop-app/状态机.md)。

## 店铺风控记录

风险事件写入即不可变。游客当前等级为 `NONE|LOW|MEDIUM|HIGH`，状态为 `NORMAL|WATCH|RESTRICTED|BLOCKED`。商户页只读列表。详细命令表见 [`risk-events/状态机.md`](./risk-events/状态机.md)。

## 店铺投诉

投诉状态为 `OPEN → ACCEPTED|REJECTED`。商户页只列表、读取和审核；Shop 提交不在本切片。终态不可再审，除非同一 `commandKey` 重放。详细命令表见 [`complaints/状态机.md`](./complaints/状态机.md)。

## 店铺售后

售后状态为 `PENDING → APPROVED|REJECTED`。`REFUNDED`/`CLOSED` 留给后续 Trade 回写，本切片商户页不写入。退货收货只推进 `return_status`。详细命令表见 [`aftersales/状态机.md`](./aftersales/状态机.md)。

## 店铺发货单

发货单状态为 `SHIPPED → DELIVERED`。发货创建为 `SHIPPED`；只有在途单可追加轨迹或确认收货。详细命令表见 [`shipments/状态机.md`](./shipments/状态机.md)。

## 店铺自定义域名

域名状态为 `PENDING → VERIFIED/FAILED`，`test` 按 TXT 命中收敛；`activate` 只作用于 `VERIFIED` 并成为该场景唯一主域名；删除进入 `DELETED` 终态并释放 host 槽。详细命令表见 [`shop-domain/状态机.md`](./shop-domain/状态机.md)。

## 发货/配送

配送规则与发货预设状态为 `ACTIVE ↔ DISABLED`，退役进入 `RETIRED` 终态。旧物理删除映射为退役。详细命令表见 [`shipping-delivery/状态机.md`](./shipping-delivery/状态机.md)。

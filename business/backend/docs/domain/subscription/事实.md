# 事实源

- Subscription 唯一拥有两类相互独立写入的事实：套餐基本信息（稳定套餐码、名称、等级、价格、计价天数、说明、默认标记、展示排序、生命周期）和套餐策略（完整权限集合、额度模板、独立 revision）。
- 套餐权限只能引用 Platform Registry 活动权限目录的只读投影；Subscription 不创建、修改或删除权限定义、菜单定义、路由定义和验证器定义。
- 旧 `subscription_role` 一对一迁移为 `subscription_plan`；旧 `role_permission.resource_code` 只有在存在可证明的当前 Registry 权限码映射时才进入套餐权限集合，禁止按旧路径或菜单名称猜测权限码。
- 旧 `price` 一对一迁移为 `price_minor`，仍表示最小货币单位；`duration_days=0` 仍表示永久，正数表示一次购买的生效天数。
- 旧 `status=1/0` 一对一迁移为 `ACTIVE/DISABLED`；目标新增 `RETIRED` 终态代替物理删除，避免已被历史订阅引用的套餐语义消失。
- 旧权限资源目录、接口目录和验证器由运行时代码与路由反射维护；目标页面仅展示 Platform Registry 活动权限目录，不再提供资源 CRUD，从而消除权限定义双事实源。
- 新建套餐不选择权限或额度；系统在同一创建事务中初始化“空权限集合 + `catalog.products=NULL`”的显式策略，管理员随后从列表行的“权限配置”入口独立修改。
- 旧系统没有 Catalog 商品额度约束时等价于不限制商品数量；目标套餐策略必须显式保存 `catalog.products` 的正数上限或 `NULL`（显式不限额），不能用缺行表达不限额。
- Subscription 唯一拥有某 `merchant_id` 在某时间窗口生效的套餐额度上限、显式不限额标记和 revision。
- Subscription 唯一拥有每个 `merchant_id` 的完整权限权益集合和单调 revision；Identity 只保存有摘要和投影时间的派生快照。
- Catalog 唯一拥有商品与 SKU，因此 `catalog.products` 的当前使用量只能由 Catalog 统计。
- Subscription 不保存商品用量、不做商品额度预占，也不接收 Catalog 的计数回写。
- 旧系统有证据的 Catalog 套餐计数器只有 `product`；目标稳定代码为 `catalog.products`，口径是同一 `merchant_id` 下全部店铺的未删除商品总数。`app_id`/`commercial_id` 不是运行时标识。
- 旧代码没有 SKU 套餐上限条款证据，因此当前契约不创建 `catalog.skus` 默认规则。
- Subscription 唯一拥有商户自助购买产生的 SaaS 订单：下单时快照套餐码/名称/价格/计价天数，状态为 `PENDING / PAID / CANCELLED`。`/merchant/plans` 只创建和查询购买中的订单；`/merchant/billing` 列出本商户订单，并由所有者关闭 `PENDING` 订单。
- 付款通道、支付单、钱包直扣和第三方载荷由 Trade 拥有。Identity 只保存 `pay_no` 与通道码引用，不复制资金事实，也不在本模块伪造收款。
- 商品用量仍由 Catalog 统计。商户订阅页只展示 Identity 拥有的额度上限，不展示或猜测 `used`。
- 套餐卡片上的“开通能力”来自该套餐权限集合对应的 Registry 权限名称，不再复制旧 `perm_resource` 菜单名。

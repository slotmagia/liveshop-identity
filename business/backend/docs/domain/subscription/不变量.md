# 不变量

1. 套餐码全局稳定且唯一；已创建套餐不能改码，`RETIRED` 套餐不能重新启用或修改。
2. 套餐基本信息 version 从 1 单调递增；基本信息修改或退役必须给出当前 expected version。权限和额度策略使用独立 `policy_revision`，两类编辑互不制造虚假版本冲突。
3. 套餐命令按稳定 `command_key` 幂等；同键同规范化载荷返回首次 canonical response，同键异载荷冲突。
4. 同时最多一个 `ACTIVE` 默认套餐。已有套餐时不能停用、退役或清除当前默认套餐；必须先把另一项活动套餐设为默认。
5. 新建/编辑套餐基本信息的命令不得携带权限或额度；新建后初始化空权限集合和显式不限额模板。
6. 套餐权限策略是有序去重的完整集合，只能引用 Platform Registry 当前活动权限码；空集合表示明确不授予任何权限。策略命令按稳定 command key 幂等并校验 expected policy revision。
7. 每个套餐必须有且只有一条 `catalog.products` 额度模板；正数表示上限，`NULL` 表示显式不限额，零和负数非法。
8. 套餐价格不得为负；`duration_days` 不得为负，零继续表示永久。
9. 套餐 `ACTIVE -> DISABLED -> ACTIVE` 合法，`ACTIVE|DISABLED -> RETIRED` 合法，`RETIRED` 为终态；退役套餐策略不可再修改。

以下 entitlement 不变量继续独立成立：

1. `(merchant_id, quota_code)` 同时只有一条当前 entitlement 事实。
2. revision 从 1 单调递增；更新必须给出当前 expected revision。
3. `(merchant_id, command_key)` 只对应一个规范化请求哈希；同键同载荷返回相同 revision，同键异载荷冲突。
4. `NULL limit_value` 才表示显式不限额；没有配置、尚未生效或已经过期都返回 `FailedPrecondition`，不能 fail-open。
5. limit 必须为正数；零不能隐式表示不限额。
6. Subscription 返回 limit 和 revision，不返回 used/remaining。Catalog 必须在自身 MySQL 事务中串行化同一商户的建品，统计当前商品数并校验 `used + adding <= limit` 后才写商品。
7. Subscription 查询超时、不可达或结果未知时，Catalog 不得写商品或确认导入。
8. `(merchant_id)` 只有一个权限权益当前态；空集合且 revision 大于零表示明确无权限，没有 state 才是未配置。
9. 权限权益命令按 `(merchant_id, command_key)` 幂等，规范化命令键和有序去重权限进入请求摘要；同键同载荷永久返回首次 canonical response，即使当前态已推进到更高 revision。
10. Identity 只能读取完整快照。旧 revision、同 revision 不同摘要、缺失或超时投影均失败关闭；商户 owner 也不能绕过 Subscription 权益。

以下商户购买不变量独立成立：

1. 商户只能购买 `ACTIVE` 且 `price_minor > 0` 的套餐；免费档只能由总后台指派。
2. 当前档若 `duration_days=0`（永久）则拒绝重复购买；限时当前档允许续费。
3. `(merchant_id, plan_id)` 同时最多一笔 `PENDING` 订单；同套餐再次下单复用该在途单。
4. 购买命令按稳定 `command_key` 幂等；同键同载荷返回首次订单，同键异载荷冲突。
5. 订单 `PAID` 与 `CANCELLED` 为终态；只有 `PENDING → PAID` 会开通或续期订阅；只有 `PENDING → CANCELLED` 会关闭未支付订单。
6. 未从 Trade 得到已支付结果前，不得把订单标为 `PAID`，也不得改写商户套餐指派。
7. 开通使用下单快照的套餐码/天数，而不是当下目录的实时改价。同档未过期续费从当前到期日顺延；换档立即生效，旧档剩余时间作废。
8. 关闭未支付订单只发生在账单菜单；套餐页不得取消。`PAID` 订单拒绝关闭。关闭后 generated `pending_slot` 变为 `NULL`，同一套餐可再下一笔 `PENDING`。
9. close 命令按稳定 `command_key` 幂等；已 `CANCELLED` 的同键重放返回首次结果，不 invent Trade 取消。

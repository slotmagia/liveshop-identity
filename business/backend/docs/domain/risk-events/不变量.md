# 店铺风控记录不变量

1. 每条风险事件和游客快照必须绑定同一 `identity_shop` 行证明的 `merchant_id + shop_id`；两个维度不得由浏览器拼接或互相替代。`app_id`/`commercial_id` 不是运行时标识。
2. 商户列表范围只来自 merch Module Session。请求不得携带 `merchantId`/`shopId`，也不得改查另一店铺。
3. `identity_risk_event` 只追加，不更新、不物理删除。历史分数快照不得被当前决策覆盖。
4. 同一店铺同一游客最多一条 `identity_visitor_risk` 当前快照；列表用它填充 `currentScore`/`currentLevel`/`visitorStatus`。
5. `visitor_id` 为 1–64 且不含空白。`reason` 为 1–64。`nickname` 最长 64，可空。`room_id >= 0`。
6. `score_before`、`score_after_decay`、`score_after`、`current_score` 均为非负整数。`score_delta` 可为负。
7. `current_level` 只能是 `NONE|LOW|MEDIUM|HIGH`。`visitor_status` 只能是 `NORMAL|WATCH|RESTRICTED|BLOCKED`。
8. 关闭或缺失店铺不能列出事件。跨店铺 JOIN 或按房间标题反查 Live 都禁止。
9. 本切片不提供写 HTTP。后续写入必须在同一事务内追加事件并条件更新游客快照版本，且不得把 Platform 原始埋点写入本表。

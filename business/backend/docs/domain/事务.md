# Identity 事务边界

| 用例 | 同一事务内必须完成 | 幂等/并发 | 事务外失败与恢复 |
|---|---|---|---|
| 创建主体和凭据 | 主体、凭据、版本、Outbox | 稳定 request ID 与凭据唯一键 | Relay 重放事件；Platform Inbox 去重 |
| 登录 | 锁定主体/凭据、更新失败次数或建立 session、插入 refresh token、Outbox | 登录限流；成功 session 使用随机 ID | Access Identity 只在事务提交成功后签发 |
| 请求登录验证码 | 锁定活动 shopCode、使同店同目的地旧 PENDING 过期、插入挑战散列与 TTL | `challengeId` 高熵唯一；`deliveryKey` 绑定 challengeId | `Dispatch` 在提交之后；发送失败不回滚挑战 |
| 核验登录验证码 | 锁定挑战、校验店铺/TTL/次数、比较散列、推进 CONSUMED 或 EXPIRED | 常数时间比较；重复核验失败关闭 | 不调用 Platform；本切片不签发会话、不升级游客 |
| 建立游客会话 | 锁定并解析活动 shopCode、创建 GUEST 主体、建立绑定 `merchant_id + shop_id` 的 session、插入 refresh token、主体与会话 Outbox | 主体/session/family/token 使用高熵随机标识和唯一键；失败整笔回滚 | Access Identity 和 cookie 只在事务提交成功后签发；客户端可在失败后重新请求，但不会复用未提交标识 |
| Refresh 轮换 | 锁定 token/session、旧 token 改 USED、插入新 token、更新 session | token hash 唯一；重复 USED 进入重用处理 | 签名失败不回滚 durable session，客户端用新 token 重试受保护流程 |
| 修改凭据或停用主体 | 条件更新、清除锁定、撤销全部活动 session/token、递增 access_version、Outbox | `expected_version` | Identity 授权读取校验版本并立即失败关闭；普通失败由 Outbox 重试 |
| 创建商户及所有者 | 商户、owner 主体/凭据、商户组织根、所有者成员、owner 授权域、Outbox | request ID 与账号唯一键 | Identity 单事务建立 owner 语义，权限仍受本模块 Subscription capability 权益约束 |
| 创建/更新店铺 | 店铺、`merchant_id`/`shop_id` 归属、版本、Outbox | `shop_id` 主键与 `expected_version` | 域名或边缘配置通过事件恢复，不进入数据库事务 |
| 更新组织结构 | 锁定组织聚合、校验父级/环、更新单元或成员、递增版本、Outbox | 条件更新；重复关系写收敛 | Identity 有效授权按组织版本读取，旧版本失败关闭 |
| 创建员工/主播身份 | 主体、凭据、ACTIVE 成员、组织关系、店铺关系、可选初始角色 grant、授权 revision、Outbox | operation ID、命名空间凭据唯一键、主播有效唯一槽 | 同库事务原子提交；失败不留下身份/授权半成品 |
| 修改员工店铺和组织范围 | 全量校验并替换关系、递增 access version、同步活动 grant version、递增授权 revision、撤销会话、Outbox | operation ID、expected access version | Identity 下次签发 Module Capability 时读取新范围；旧能力在配置 TTL 内失效 |
| 创建平台操作员 | 主体、OPERATOR workforce、GLOBAL 凭据、非空初始平台角色 grant、授权 revision、Outbox | operation ID + idempotency key；由组织与 operation ID 派生稳定 subject | 任一步失败整笔回滚，不留下无角色或无凭据主体 |
| 启停平台操作员/商户员工 | 锁定并条件更新 subject 与 workforce、同步 grant access version、递增授权 revision、停用时撤销 session/refresh、Outbox | expected identity/access version；相同幂等键绑定请求摘要 | system role、最后一个平台操作员、owner、跨组织或多 membership 目标失败关闭 |
| 重置凭据 | 条件更新 credential version、清除锁定、撤销目标全部 session/refresh、Outbox | expected credential version；密码只以稳定摘要参与幂等请求散列，bcrypt 盐值不参与 | 同事务提交；重复命令返回原版本结果且不重复写事件 |
| 主动撤销会话 | 锁定并验证目标属于管理范围或当前登录主体，撤销指定或全部 session 与 refresh token、Outbox | operation ID + idempotency key；重复撤销收敛；自助撤销原因 `SELF_REVOKED` | 不调用外部系统，无提交后失败窗口 |
| 创建/更新/删除客服账号 | 命令键、`merchant_id + shop_id` 校验、客服账号条件写入与完整响应账本 | command key + 请求摘要；更新/删除校验 expected version；同店唯一键 | 无事务外副作用；提交结果未知时用原 key 重试并重放结果 |
| 保存店铺客户隐私 | 命令键、未关闭店铺锁定、缺行或版本条件写入、Outbox、完整响应账本 | command key + 请求摘要；首次 `expectedVersion=0`；后续校验当前版本 | 平台叠加层拒绝发生在写事务外；提交未知时用原 key 重试并重放结果 |
| 保存/发布店铺政策 | 命令键、未关闭店铺锁定、叠加层读、归档旧发布版、插入或推进政策行、完整响应账本 | command key + 请求摘要；发布校验 expected version；同店同类型版本号唯一 | 草稿保存不看叠加层；发布在同一事务拒绝非 active 叠加层；提交未知时用原 key 重试 |
| 创建/轮换/启停店铺私有应用 | 命令键、未关闭店铺锁定、叠加层读、密钥散列、条件更新与完整响应账本 | command key + 请求摘要；轮换/启停校验 expected version；`client_id` 唯一 | 创建/轮换/启用拒绝非 active 叠加层；停用始终允许；明文密钥只进命令账本；提交未知时用原 key 重试 |
| 列出店铺风控事件 | 只读事务内校验未关闭店铺并分页 JOIN 当前游客快照 | 范围只来自 merch Session；过滤条件规范化 | 关闭店铺返回不存在；本切片不写事件或快照 |
| 列出/读取/审核/确认收货售后 | 只读或写事务内校验未关闭店铺；审核/收货写命令账本与条件更新 | command key + 请求摘要；写命令校验 expected version | 不向 Trade 发退款，不改 Catalog 库存；提交未知时用原 key 重试 |
| 列出/读取/发货/追加轨迹/确认收货 | 只读或写事务内校验未关闭店铺；写命令账本与发货单条件更新 | command key + 请求摘要；发货插入唯一订单；轨迹/确认收货校验 expected version | 不更新 Trade 订单状态，不请求承运商；提交未知时用原 key 重试 |
| 创建/校验/设主/删除店铺自定义域名 | 命令键、未关闭店铺锁定、叠加层读（删除除外）、条件更新与完整响应账本 | command key + 请求摘要；校验/设主/删除校验 expected version；未删除 host 唯一 | TXT 查找在写事务外；查找失败关闭不推进 `VERIFIED`；创建/校验/设主拒绝非 active 叠加层；删除始终允许；提交未知时用原 key 重试 |
| 创建/更新/启停/退役配送规则与发货预设 | 命令键、未关闭店铺锁定、默认预设切换、条件更新与完整响应账本 | command key + 请求摘要；更新/启停/退役校验 expected version；同店未退役最多一个默认 | 叠加层拒绝发生在写事务外；退役不物理删除；提交未知时用原 key 重试 |

## Registry 外部投影与 Subscription 内部读模型失败窗口

Platform Registry 与 Identity 不能形成一个事务；Subscription capability 与授权读模型则共享 Identity 数据库：

1. Platform 在自己的事务内追加带稳定 event ID 和单调 revision 的事件。
2. Identity Inbox 去重，拒绝旧 revision 覆盖新 Registry 投影，并在同一事务更新投影和 Inbox。
3. Subscription 权益命令在 Identity 数据库内写入事实；本地同步器按单调 revision 原子刷新授权读模型，不经过网络调用。
4. 投影缺失、版本为零或 Contribution/权限不一致时，角色写入与 Module Capability 签发失败关闭。
5. Module Capability 在同一数据库一致性快照读取活动 Contribution、权限目录、权益与有效授权，不能拼接不同 revision 的缓存。

所有事务使用请求 context、有界超时和 MySQL `REPEATABLE READ`。只对 1213/1205 做有界退避重试；非幂等外部调用不在事务中执行。

所有 Admin/Merch 非只读页面请求在进入上述写事务之前执行当前授权复核。复核使用 `REPEATABLE READ` 只读事务，不更新业务事实：旧 Capability 在 session 撤销、context version、subject/organization version、授权 revision、Registry revision、平台边界 revision 或商户权益 revision/投影新鲜度任一变化后立即拒绝写入。GET/HEAD 保持短期 Capability TTL 语义。

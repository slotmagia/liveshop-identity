# 商户物流发货事实源

Identity 的 fulfillment capability 是店铺发货单与轨迹的唯一事实源。菜单在商户后台「履约营销 / 物流发货」。Trade 拥有订单资金；本表只保存订单主键引用，不复制订单行，也不向 Trade 发 Outbox。

## 旧系统到当前模型的逐项对照

| 旧表/接口字段 | 旧语义证据 | 当前字段 | 迁移规则 |
|---|---|---|---|
| 旧接口 `GET /commercial/logistics/list` | 本店发货单分页 | `GET /merch/identity/shipments` | 不保留 `/commercial/*` 别名 |
| 旧接口 `GET /commercial/logistics/detail/{orderId}` | 按订单打开物流 | `GET /merch/identity/shipments/{shipmentId}`；列表可按 `orderId` 筛选 | 资源主键是发货单，不再把订单号当 path 资源 |
| 旧接口 `POST /commercial/logistics/ship` | 填写承运商/单号发货 | `POST /merch/identity/shipments` | 集合 `create`；同店同订单唯一 |
| 旧接口 `POST /commercial/logistics/trace` | 追加轨迹节点 | `POST /merch/identity/shipments/{shipmentId}/traces` | 嵌套集合 `create` |
| 旧接口 `POST /commercial/logistics/confirm` | 确认收货 | `POST /merch/identity/shipments/{shipmentId}/close` | 旧 `confirm` 映射为封闭方法词 `close` |
| `order_id` | 被发货订单 | `order_id` | Trade 订单引用；不建外键 |
| `carrier` / `tracking_no` | 承运商与运单号 | `carrier` / `tracking_no` | trim 后 1–64 |
| `status` 自由字符串 | 发货状态 | `SHIPPED` / `DELIVERED` | 发货进入 `SHIPPED`；确认收货进入 `DELIVERED` |
| `traces[].node` / `ts_ms` | 轨迹节点 | `traces[].node` / `occurredAt` | 追加时服务端写时间；节点 1–200 |
| `page` / `per_page` | 分页 | `page` / `pageSize` | 默认 20，最大 100 |
| `appid` / `commercial_id` | 旧运行时隔离键 | 非运行时 | 只从 merch Module Session 读取 `merchant_id + shop_id` |

## 唯一事实源

- 发货单：`identity_shipment`，归属同一 `identity_shop` 行证明的 `merchant_id + shop_id`。
- 命令账本：`identity_shipment_command`，稳定 `commandKey` 幂等回执。
- `order_id` 只是 Trade 主键引用；本模块不读取订单库，也不更新订单履约轴。
- 本切片商户页提供列表、详情、发货、追加轨迹和确认收货。Shop 查询/确认是后续 shop surface。
- 关闭店铺后列表与写入视为范围不存在。发货单不物理删除。
- 「设置 / 发货/配送」是配送规则，不在本页。

# 商户物流发货对外契约

商户后台页面继续使用菜单路由 `/logistics`，经 Gateway 调用以下唯一主契约。范围只来自 merch Module Session 的 `merchantId + shopId`。

| 方法与路径 | 用途 | 幂等 |
|---|---|---|
| `GET /merch/identity/shipments` | 分页列出当前店铺发货单 | safe |
| `GET /merch/identity/shipments/{shipmentId}` | 读取一条本店发货单（含轨迹） | safe |
| `POST /merch/identity/shipments` | 为指定订单发货 | `commandKey` |
| `POST /merch/identity/shipments/{shipmentId}/traces` | 向 `SHIPPED` 发货单追加轨迹 | `commandKey` |
| `POST /merch/identity/shipments/{shipmentId}/close` | 确认收货，进入 `DELIVERED` | `commandKey` |

列表/详情要求 `identity.shipment.read`。发货、轨迹和确认收货要求 `identity.shipment.manage`。

响应 camelCase：`id`、`orderId`、`carrier`、`trackingNo`、`status`、`traces`、`version`、`createdAt`、`updatedAt`。轨迹项为 `occurredAt`、`node`。不返回 `merchantId`/`shopId`。写响应另含 `replayed`。

查询参数：`orderId`、`status`、`page`、`pageSize`。

旧路径 `/commercial/logistics/*` 不再提供。浏览器不得提交 `appId`/`commercialId` 或店铺 ID。Shop 查询/确认不在本契约。设置页「发货/配送」不走本契约。

## 事件

本切片不发布 Outbox。后续若要推进 Trade 订单履约轴，必须走 Trade 公开幂等命令。

## 菜单与权益

Manifest Contribution `identity.merch.logistics` 开放 `/merch/identity/shipments` 的 GET 与 POST。菜单是否出现取决于商户套餐是否包含 `identity.shipment.read`。

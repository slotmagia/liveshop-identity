# 旧商户后台「物流发货」迁移对照

## 旧页面与接口证据

- 页面入口：`src/views/business/logistics`。
- 菜单：履约营销 / 物流发货，路由 `/logistics`，资源 `menu.logistics`。
- 旧接口：`GET /commercial/logistics/list`、`GET /commercial/logistics/detail/{orderId}`、`POST /commercial/logistics/ship`、`POST /commercial/logistics/trace`、`POST /commercial/logistics/confirm`。
- 旧视图 `fulfillmentpb.Shipment`：`id`、`order_id`、`carrier`、`tracking_no`、`status`、`traces`、时间戳。
- 旧行为：筛选列表；打开详情；填写承运商/单号发货；追加节点；确认收货。
- 实时承运商追踪、电子面单和配送规则不在本页。

## 字段映射

| 旧字段 / 行为 | 目标字段 / 行为 | 迁移规则 |
|---|---|---|
| `appid` / `commercial_id` | `merchant_id + shop_id` | 只从 merch Module Session 读取。 |
| `detail/{orderId}` | `{shipmentId}` + 列表 `orderId` | 发货单是资源；订单号是筛选与创建字段。 |
| `ship` | `create` | 封闭集合动词。 |
| `trace` | `traces.create` | 嵌套在发货单下。 |
| `confirm` | `close` | 封闭方法词；确认收货结束在途生命周期。 |
| `per_page` | `pageSize` | 默认 20，最大 100。 |
| 任意 `status` 字符串 | `SHIPPED` / `DELIVERED` | 拒绝未登记状态。 |
| 页面结构 | Host 查询卡 + 数据卡表格 + `hostFormModal` | 分页在数据卡 footer；失败用 `notify()`。 |

## 页面迁移结果

- 菜单目录、名称和 `/logistics` 路由保持不变。
- Contribution 为 `identity.merch.logistics`。
- 页面不提供静态假数据；空列表合法。
- 不迁移 Shop 确认收货、配送费率或 Trade 订单状态。

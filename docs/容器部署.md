# Identity 容器部署

Identity 拥有主体、会话、商户/店铺、授权、订阅以及四端 contribution artifact。它消费 Platform 的活动 Registry 和共享证书卷，不签发 Platform 控制面身份。

## 完整环境

```powershell
pwsh -File .\deploy-local-containers.ps1 -Fresh
```

根脚本会在全部模块注册后导入本地授权、等待 revision 收敛，并做 Admin / Merchant / Shop 冒烟。单独启动本模块不会完成这些步骤。

## 本模块脚本

```powershell
pwsh -File .\business\backend\tools\up-local.ps1
pwsh -File .\business\backend\tools\up-local.ps1 -Register
pwsh -File .\business\backend\tools\up-local.ps1 -Fresh -Register
pwsh -File .\business\backend\tools\down-local.ps1
pwsh -File .\business\backend\tools\down-local.ps1 -Volumes
```

| 脚本 | 作用 |
|---|---|
| `tools/up-local.ps1` | 校验 `liveshop-grpc-certs` 与 Platform `/readyz`，启动 MySQL / 迁移 / 本地种子 / 后端 / 四个 artifact |
| `tools/up-local.ps1 -Register` | 注册并激活本仓库 `module.json` |
| `tools/down-local.ps1` | 停止本 Compose 项目 |
| `tools/register-local.ps1` | 仅注册/激活 |

## 依赖

- 外部网络 `liveshop-local`
- 卷 `liveshop-grpc-certs`（Platform 已引导）
- Platform `http://127.0.0.1:18082/readyz`

容器内 Registry 地址为 `platform:19082`。本模块不向宿主机发布 gRPC `19092`（避免与本机 Kafka 冲突）；其他容器通过 `identity:19092` 访问。

## 端口与服务

| 服务 | 地址 |
|---|---|
| Identity HTTP | `http://127.0.0.1:18092` |
| MySQL | `127.0.0.1:33072` |
| Admin artifact | `http://127.0.0.1:15201` |
| Merch artifact | `http://127.0.0.1:15202` |
| Shop remote ESM | `http://127.0.0.1:15203/identity-shop.js` |
| Live remote ESM | `http://127.0.0.1:15204/identity-live.js` |

Compose 中的 Access Identity / Module Capability 私钥仅用于本地。生产必须改用受管密钥，并只向 Gateway 与业务模块发布对应公钥。

## Compose 与镜像

- Compose：`business/backend/deploy/compose.local.yml`
- 后端：`business/backend/deploy/Dockerfile`
- 前端：`business/backend/deploy/frontend.Dockerfile`

## 常见失败

- 缺少 `liveshop-grpc-certs`：先启动 Platform。
- 启动后 `/readyz` 失败：活动 Registry 快照缺失或投影超过 `max_staleness`。
- `release_immutable`：升高 `module.json` 版本或全栈 `-Fresh`。

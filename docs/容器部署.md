# Identity 容器部署

Identity 拥有主体、会话、商户/店铺、授权、订阅以及四端 contribution artifact。它消费 Registry 的活动快照和共享证书卷，通知 gRPC 仍打 Platform，不签发 Platform 控制面身份。

## 完整环境

```powershell
pwsh -File .\deploy-local-containers.ps1
```

默认保留 MySQL 命名卷。需要空库时才加 `-Fresh`。

根脚本会在全部模块注册后导入本地授权、等待 revision 收敛，并做 Admin / Merchant / Shop 冒烟。单独启动本模块不会完成这些步骤。

## 本模块脚本

```powershell
pwsh -File .\business\backend\tools\up-local.ps1
pwsh -File .\business\backend\tools\up-local.ps1 -Register
pwsh -File .\business\backend\tools\up-local.ps1 -Fresh -Register
pwsh -File .\business\backend\tools\down-local.ps1
pwsh -File .\business\backend\tools\down-local.ps1 -Volumes
```

| 脚本 | 作用 |
|---|---|
| `tools/up-local.ps1` | 校验 `liveshop-grpc-certs` 与 Registry `/readyz`，启动 MySQL / 迁移 / 本地种子 / 后端 / 四个 artifact |
| `tools/up-local.ps1 -Register` | 注册并激活本仓库 `module.json` |
| `tools/down-local.ps1` | 停止本 Compose 项目 |
| `tools/register-local.ps1` | 仅注册/激活 |

## 依赖

- 外部网络 `liveshop-local`
- 卷 `liveshop-grpc-certs`（Registry 已引导）
- Registry `http://127.0.0.1:18070/readyz`

容器内 Registry gRPC 为 `registry:19070`（`server_name: registry`）。通知仍打 `platform:19082`。本模块不向宿主机发布 gRPC `19092`（避免与本机 Kafka 冲突）；其他容器通过 `identity:19092` 访问。

## Compose 与镜像

- Compose：`business/backend/deploy/compose.local.yml`
- 后端：`business/backend/deploy/Dockerfile`
- 前端：`business/backend/deploy/frontend.Dockerfile`（`npm ci` 从 npmjs 安装 `@liveshops/host-sdk@0.3.4` 与 `@liveshops/design-tokens@1.5.3`，不 COPY Platform 源码）

## 常见失败

- 缺少 `liveshop-grpc-certs`：先启动 Registry。
- 启动后 `/readyz` 失败：活动 Registry 快照缺失或投影超过 `max_staleness`。空库首次启动仍 fail-fast；已有 `identity_registry_projection_state.revision > 0` 时 Registry 暂时不可达仍可起来，但签发会按 staleness 关闭。
- `release_immutable`：全栈脚本会自动注册下一个补丁版本并保留业务库。不要用 `-Fresh` 清库。

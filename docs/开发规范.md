# LiveShop 通用开发规范

> 位置：本仓库根目录 `docs/开发规范.md`  
> 生效：2026-08-17  
> 适用范围：Identity、Catalog、Trade、Live、Platform、Gateway  
> 本文件是本仓库完整通用开发规范。开发只读本仓库文档，不要引用本模块目录外的文档。

按层次阅读，不要跳层实现：

| 章 | 层次 | 管什么 |
|---|---|---|
| 1 | 原则与发布边界 | 谁拥有事实、六个仓库职责 |
| 2 | 工程目录结构 | 仓库根、backend、frontend、capability |
| 3 | 目录功能边界 | 模块 / capability 允许与禁止 |

| 7 | 初始化、引用、组件 | 启动链、依赖、共享组件 |

## 1. 原则与发布边界

1. 一个业务事实只有一个所有者；跨模块只走公开 HTTP / gRPC / 事件。
2. 按垂直能力交付：领域、接口、权限、页面、迁移、测试、Manifest 一次齐。
3. 契约先于实现。`module.json` / Proto / migration 先于业务代码。
4. 直接演进唯一主路径。不建 fallback、双写、旧 URL 别名。
5. 店铺隔离只用 `merchant_id + shop_id`。禁止运行时 `app_id` / `commercial_id`。禁止 `commercial_id → merchant_id`、`shop_id → department_id`。
6. `admin` / `merch` / `shop` / `live` 是交付 surface，不是模块名，也不是四套 Identity。
7. 代码、契约、文档同一变更交付。验证的是不变量和最终状态，不是“代码写完了”。

| 仓库 | 拥有 | 禁止 |
|---|---|---|
| Identity | 主体、凭据、会话、组织、商户、店铺、授权、订阅、客户、履约、风险、客服、商户治理 | Registry、支付、商品、直播房间 |
| Catalog | 类目、商品、SKU、库存、购物车、素材资产、营销、经营分析、AB 映射 | 原始埋点、订单、身份、直播场次 |
| Trade | 结账、订单、支付、退款、钱包、结算、拍卖 | 物流售后、秒拼活动、商品主数据 |
| Live | 房间、场次、互动、秒拼编排、直播分析 | 订单资金、商品事实、客服账号 |
| Platform | Registry、配置、审计、通知通道、存储通道、遥测归因、直播 Provider、翻译、Host SDK、Design Tokens | IAM 签发、业务库 |
| Gateway | 无状态代理、四端 Host、Host Runtime | 业务事实、IAM、模块注册 |

内部 capability（subscription、media、marketing、auction、groupbuy、notification 等）不得再建成独立仓库、数据库或 Manifest。

## 2. 工程目录结构

### 2.1 业务模块（Identity / Catalog / Trade / Live）

现行仓库根（以实际代码为准，不是 TEAM 旧稿里的扁平 `backend/`）：

```text
liveshop-<module>/
├─ docs/                     # 本规范
├─ go.work
├─ protocol/                 # 独立 Go module；只放本模块 proto
│  └─ proto/<module>/v1/
└─ business/
   ├─ AGENTS.md
   ├─ module.json            # 唯一发布清单
   ├─ ownership.yaml
   ├─ dependency-policy.yaml
   ├─ backend/
   ├─ frontend-admin/        # 按需，iframe
   ├─ frontend-merch/
   ├─ frontend-shop/         # 按需，remote ESM
   └─ frontend-live/
```

`business` 依赖 `protocol` 的发布产物；`protocol` 绝不依赖 `business`。不需要的 surface 不建空前端工程。

```text
business/backend/
├─ cmd/archcheck/
├─ configs/<module>.yaml     # 唯一完整配置
├─ docs/                     # 模块开发规范、domain 五件套
├─ deploy/                   # 本地 Compose 与镜像
├─ migrations/               # 只追加
├─ tools/                    # verify / up-local / down-local / register-local
└─ internal/<module>/
   ├─ app/                   # dependencies / surfaces / bootstrap / run
   ├─ config/                # schema + 启动校验
   ├─ capability/<name>/     # 内部能力：model、usecase、仓储端口
   ├─ application/<surface>/ # admin | merch | shop | live
   │  ├─ api/http/v1/<domain>/
   │  ├─ appmodel/
   │  ├─ service/
   │  ├─ logic/
   │  ├─ controller/http/
   │  └─ router/http.go
   ├─ biz/                   # 仅跨 capability 的模块级用例
   ├─ data/<name>/           # mysql 生产适配；memory 仅测试
   ├─ worker/                # Outbox / Inbox / 对账
   ├─ common/                # authctx、middleware、web、server
   └─ cmd/                   # 进程入口
```

capability 子目录**不是**微服务：禁止自建 `go.mod`、`module.json`、独立库连接或进程入口。

### 2.2 Platform

```text
liveshop-platform/
├─ docs/
├─ protocol/
└─ business/
   ├─ module.json
   ├─ backend/internal/…     # application/admin + controlplane + biz/capability
   ├─ packages/host-sdk/
   ├─ packages/design-tokens/
   └─ frontend-admin/        # 仅 Admin 控制面；禁止 merch/shop/live 空目录
```

### 2.3 Gateway

```text
liveshop-gateway/
├─ docs/
├─ backend/internal/gateway/
│  ├─ app/
│  ├─ common/server/         # 路由快照、鉴权、CORS、反向代理
│  └─ cmd/
├─ packages/host-runtime/
├─ frontend-admin/           # Host，不是模块 contribution
├─ frontend-merch/
├─ frontend-shop/
├─ frontend-live/
└─ tools/
```

Gateway **不得**建立 `protocol/`。Host 不得导入业务模块源码。

### 2.4 前端 contribution

```text
business/frontend-<surface>/
├─ package.json              # name = @liveshop/<module>-<surface>
├─ src/main.ts               # iframe：connectToHost
│  或导出 RemoteModule       # shop/live：mount / unmount
├─ src/pages/ 或 views/
└─ AGENTS.md
```

admin / merch = iframe；shop / live = remote ESM。Host 只在 Gateway。

## 3. 目录功能边界

每个 capability 必须有 `README.md`，写清拥有什么、不拥有什么。跨模块禁止直连对方库。新增 capability 先改 README 和 domain 五件套，再写代码。

领域文档（业务模块与 Platform）固定五份，缺一不能实现：

`事实.md` · `不变量.md` · `状态机.md` · `事务.md` · `外部契约.md`

| 模块 | Capability | 不拥有 |
|---|---|---|
| Identity | auth、subject、merchant、shop、workforce、authorization、subscription、customer、fulfillment、risk、customer_service、merchant_governance | 短信投递证据、对象存储、直播房间、支付 |
| Catalog | catalog、inventory、cart、media、marketing、analytics、ab_mapping | 原始埋点、订单、IAM、直播场次、存储 Secret |
| Trade | checkout、order、payment、wallet、settlement、auction | 物流售后、秒拼活动、商品 SKU |
| Live | live、groupbuy、analytics | 订单资金、商品主数据、客服账号、Provider Secret |
| Platform | notification、storage、telemetry、liveprovider、localization | IAM 签发、素材资产、房间场次、游客风险 |
| Gateway | 无业务 capability | 一切业务事实与模块注册 |

跨 capability 写表必须走模块级用例的同一事务。任何 capability 不得直接改另一个 capability 的表。

## 4. 后端规范

### 4.1 分层与依赖

依赖方向：`application/<surface>` → `capability/<name>` / 模块级 `biz` → 仓储端口 ← `data/<name>`。

| 层 | 职责 | 禁止 |
|---|---|---|
| `capability/*/model`、`biz/model` | 事实、不变量、状态机、领域错误 | GoFrame、SQL、HTTP DTO |
| `capability` usecase / `biz` | 用例与仓储端口 | `application`、驱动、Req/Res |
| `data` | SQL、事务、锁、Outbox | 页面逻辑、跨模块库 |
| `api/http` | `g.Meta`、XxxReq / XxxRes | 导入 `biz`/`data`、protobuf 当 JSON |
| `appmodel` | 传输中立出入参 | `Req`/`Res` 后缀 |
| `service` | 边界接口 | 实现、传输 DTO |
| `logic` | claims → 用例 | GoFrame、SQL、跨 surface |
| `controller` | DTO ↔ appmodel | 鉴权、SQL、biz 直调 |
| `router` | 分组、中间件、Bind | 业务规则 |
| `common/middleware` | **唯一**把凭证变成上下文 | 业务规则 |
| `app` | 装配与生命周期 | 业务规则、读环境变量 |

surface 之间禁止相互导入。`application/<surface>` 必须与 `frontend-<surface>` 和 Manifest contribution 一一对应。Trade 的 `application/workload` 只承载 mTLS gRPC，不对应页面。Platform 的 `controlplane` 不背页面贡献，浏览器不得直连。

### 4.2 通用初始化

```text
cmd → -config 唯一 YAML → config.Validate
    → gfinit.MustInit
    → app/dependencies.go 显式构造 DB、verifier、仓储
    → app/surfaces.go 装配各 surface
    → common/server + grpcserver 唯一组合
    → app/run.go 生命周期 / 优雅停机
```

禁止：环境变量覆盖、隐式 overlay、`init()` 注册全局单例、代码里写死密钥。缺配置必须启动失败。

Identity 签发 Module Capability；其他模块只构造 `Verifier`。Issuer 必须为 `liveshop-identity`。Gateway 按 Manifest 转发，不写模块硬编码路由。

### 4.3 编码

- HTTP：GoFrame；`g.Meta` 的 path + method 与 `module.json` **逐字相同**。
- 跨模块同步：对方 `protocol` 生成的 gRPC client，带 deadline；仅 `idempotent|safe` 才自动重试。
- 跨模块异步：本模块 Outbox → 对方 Inbox；禁止直改对方表。
- 写命令：稳定 `commandKey` / `idempotencyKey` + `expectedVersion`；物理删除改为 `RETIRED` / `CLOSED` 等终态。
- JSON 字段 camelCase；表名 `<module>_<aggregate>`；migration `NNN_描述.sql` 只追加。
- 领域错误放 `model.Err*`；`common/web` 是 HTTP 状态的唯一映射。gRPC 状态码禁止从 HTTP 推导。
- 格式门禁用 `gofmt -l`，不要用会就地改写的 `go fmt` 当检查。
- 密钥不回传明文；Provider Secret 只存密文或引用。
- 源码与文档统一 UTF-8；MySQL 全链路 `utf8mb4`。

### 4.4 新增能力顺序

```text
1. domain 五件套 + capability README
2. module.json operation / 权限 / contribution
3. model → usecase/port → data 事务适配
4. 跨 capability 才进入模块级 biz
5. application/<surface>：api → appmodel → service → logic → controller → router 中间件
6. app 显式注入新依赖
7. 前端 artifact 与 allowedRoutes
8. verify-domain + verify-fast + 放行/拒绝鉴权测试
```

## 5. 前端与 UI 规范

### 5.1 三类前端不可混

| 类型 | 位置 | 可做 | 不可做 |
|---|---|---|---|
| Host | Gateway `frontend-*` | 布局、导航、装载 artifact、会话 | 业务事实、业务 API 编排 |
| 公共包 | Platform `host-sdk`、`design-tokens` | 握手、HTTP 客户端、组件 | 业务页面 |
| 模块 contribution | `frontend-<surface>` | 本模块页面与本模块 API | 读父 DOM、自造 token、第二套 UI |

凭证只来自 `connectToHost()` 或 `mount` 的 context。禁止 localStorage / cookie / URL 读 token。禁止手写 Gateway 地址和 Authorization 头。

### 5.2 后台页面结构（admin / merch）

```text
Host 主内容滚动区
├─ 菜单说明卡（Host 从活动 Manifest 的 title / description 渲染）
├─ 查询卡（有筛选时）
└─ 数据卡
   ├─ 工具栏：刷新、新增、导入、导出、批量
   ├─ 表格 / 树 / 集合
   └─ 分页工具栏
```

- 模块使用 `page({ showSummary: false })`，禁止复制标题和说明。
- 查询用 `searchForm()`，由 `searchCard()` 单独承载。
- 集合用 `dataCard()`；页面级操作只进数据卡工具栏；行操作留在行内。
- 三张卡左右边界对齐；contribution 根节点不得加水平 padding。
- iframe 透明、无圆角、无阴影，经 Host SDK 上报高度；禁止嵌套纵向滚动。
- Host 根文档 `overflow: hidden`；纵向滚动只发生在 `data-page-scroll-container`。

### 5.3 查询表单

- 宽屏 6 个等宽字段列 + 1 个操作列。普通字段各占 1 列；只有 `kind: 'date-range'` 占 2 列。
- 操作组（折叠/展开、搜索、重置）固定在第一行最右侧。单行不显示折叠按钮。
- 字段变化由共享 `searchForm()` 自动搜索：下拉和日期立即搜，文本防抖 300ms。页面不得手写查询字段监听。
- 级联下拉必须在 `onSearch` 内同步选项，替换 option 后调用 `refreshSearchSelect()`。
- `kind: 'select'` 使用共享可搜索下拉，点选即选中；空值表示全部。菜单必须 portal 到当前文档 `body`，使用 `position: fixed` 和 `--ls-z-popover`。禁止把菜单留在模态框 Body 内，禁止页面写局部 `z-index` 或第二套 combobox。
- `page` / `pageSize` / `perPage` / `limit` 不得进入查询表。分页在 `dataCard.footer` 的 `pagination()`。

### 5.4 模态框与遮罩

- 普通表单、提示、确认、可序列化只读详情：只允许 `hostFormModal()`。打开前后 iframe 尺寸和 Host 布局不变，只有 Host 顶层遮罩覆盖 `100vw × 100dvh`。
- 无法表示为 Host 字段的富交互：共享 `modal()` + 成对 `hostOverlay()`。
- Header / Footer 固定，只有 Body 滚动。禁止 HTML5 fullscreen、自建 backdrop、访问父 DOM。
- 权限多选必须 `kind: 'checkbox-tree'`，禁止 textarea 填权限码。
- 可搜索下拉是独立浮层，不是模态框子层。层级必须为：页面 < iframe 模态 `--ls-z-modal` < Host overlay `--ls-z-host-overlay` < Host 表单模态 `--ls-z-host-modal` < 消息提示 `--ls-z-toast` < 下拉 `--ls-z-popover`。打开模态时关闭已展开的下拉。业务页不得覆盖这些 z-index。

### 5.5 商城 / 直播

- Shop 用 `design-tokens/storefront`，不是后台卡片。
- 无数据时用真实空状态，禁止假列表。
- 页面 route 保持旧商城 / 直播 URL；详情页不进五栏导航。

### 5.6 组件与样式

- 按钮、表单、卡片、表格、价格、状态、弹窗、消息提示不得在模块内重做一套。
- 颜色字号只用 design-tokens 变量；禁止 `var(--ls-x, #fallback)`。
- 禁止为静态结构拼 `innerHTML`。
- Gateway Host 的 Tailwind 只能 `presets: [@liveshops/design-tokens/tailwind-preset]`，禁止在 `theme.extend` 写第二套配色。

### 5.7 消息提示

- 成功、失败、警告、复制结果等瞬时反馈只允许 `notify()`。禁止写进查询卡、数据卡 `status`、工具栏或表格上方。
- `notify(text, tone)` 由 Host 在顶层文档右上角浮层展示，不占页面布局。iframe contribution 不得在模块文档里画提示条。`danger` / `warning` / `success` / `info` 为提示语义。
- 加载中、条数统计、分页摘要不得作为消息提示；空集合用 `emptyState()` 或表格 `empty`。
- 表单字段校验错误留在 `hostFormModal().setError()`，不改走 `notify()`。
- `statusLine()` 仅兼容旧调用：有语义的 `set()` 转发到 `notify()`，不再向页面写入文案。新页面不要把 `statusLine().element` 放进 `dataCard`。

## 6. 命名与 Manifest

### 6.1 三套名字空间

| 名字空间 | 形状 | 可否与旧站相同 |
|---|---|---|
| API path | `/<surface>/<module>/<domain>/...` | 否 |
| Operation id | `<module>.<surface>.<domain>.<feature?>.<method>` | 否 |
| 页面 route | 旧菜单 / 旧商城 URL | **是，必须保持** |
| 权限码 | `<module>.<resource>.<action>` | 否（不含 surface） |
| 真实贡献 | `<module>.<surface>.<page>` | — |
| 占位贡献 | `<module>.placeholder.<surface>.<page>` | — |
| artifact | `@liveshop/<module>-<surface>` | — |

去掉 `{param}` 后，path 静态段必须还原 id 的 domain / feature。集合动词（`list/get/create/update/replace/delete`）不写进 path 末段；命令动词（`retire/revoke/preview/enable/…`）必须是 path 末段。子资源留在父路径下，不要把 sessions 提到模块根。

Platform id **必须含 surface**：`platform.admin.sms.channels.list`。禁止 `put/save/detail/state/set-*`。已发布 id 改名升 major，不留别名。

正例：`identity.admin.subscription.plans.retire` → `POST /admin/identity/subscription/plans/{planId}/retire`

### 6.2 封闭方法词

`list` `get` `create` `update` `replace` `delete` `retire` `close` `enable` `disable` `revoke` `revoke-all` `reset` `preview` `review` `test` `activate` `deactivate` `intervene` `publish` `export` `import` `import-preflight` `import-template`

path 参数 camelCase + `Id`：`{planId}` `{skuId}`。主体用 `{subject}`。禁止 `{planID}` `{commercialId}` `{action}`。

### 6.3 登记 domain（新增先登记）

- Identity：`users` `members` `organization-units` `directory` `account` `profile` `authorization` `subscription` `merchants` `shops` `shop-categories` `customer-accounts` `merchant-governance` `privacy` `policies` `apps` `risk-events` `complaints` `aftersales` `shipments` `domains` `shipping-delivery` `languages` `login` `addresses` `wishlist`
- Catalog：`categories` `products` `inventory` `skus` `cart` `assets` `coupons`
- Trade：`checkouts` `orders` `checkout` `payment`（`types`/`channels`）`payments` `wallets` `finance` `settlements` `auctions`
- Live：`rooms` `sessions` `groupbuy`
- Platform：`registry` `settings` `audit` `live-providers` `sms` `email` `storage` `notify-events` `edge`

### 6.4 Manifest 要点

`module.json` 是机器契约，同时被 archcheck、Registry、Gateway、Identity/Host 消费。

- `authentication` 与 `requiredPermissions` 必须在对应 router 挂中间件真正执行。
- 每个已暴露 surface 保留 `GET /<surface>/<module>/health`。
- contribution 的 `title` / `description` 必填；`allowedRoutes` 只覆盖本页真实请求。
- 前端 `api.request` 与 `g.Meta` 必须与 Manifest `path` 逐字相同。
- `frontend.actions[].target` 只能是 operation id、Host event、导航 route 或 module export。

新增按本章写，不按旧 id 抄。已发布且尚未升 major 的不一致项记在本仓库 `docs/命名规范检查.md`，不要当新接口模板。

## 7. 初始化、引用与组件

### 7.1 接入链路

```text
module.json → Platform Registry 激活
           → Identity 按 contribution 签发 Module Capability（≤5 分钟）
           → Gateway 按 surface + method + path 转发
           → 本模块 middleware 验签并执行权限
```

排查：401 看 token；403 先看 `X-Liveshop-Surface`，再看 `allowedRoutes`，最后看权限码；404 说明尚未注册。CORS 失败时核对 Gateway origin 清单，容器内使用服务名而非 `127.0.0.1`。

### 7.2 允许的依赖

| 依赖 | 用途 | 禁止 |
|---|---|---|
| `kernel-go` | 身份校验、生命周期、日志 | 放入业务模型 |
| 本模块 `protocol` | 对外 gRPC / 事件 | 依赖 `business` |
| 他模块 `protocol` 发布版 | 跨模块调用 | 拷贝对方 proto、导入对方 `internal` |
| `@liveshops/host-sdk` | 握手与 HTTP | 自建 axios 带 token |
| `@liveshops/design-tokens` | UI 组件与令牌 | 复制组件、第二套配色 |
| GoFrame | 本模块 HTTP | 在 `biz/model` 中使用 |
| `@liveshop/host-runtime` | **仅 Gateway Host** | 业务模块依赖 |

业务模块必须安装 npm 已发布的 `@liveshops/host-sdk@0.3.4` 与 `@liveshops/design-tokens@1.5.3`；禁止 `file:` 指向 Platform 源码。这两个包只在 Platform 仓库用 workspace 维护。

### 7.3 共享组件（后台）

必须使用、禁止再造：

`page` · `searchCard` · `searchForm` · `dataCard` · `pagination` · `hostFormModal` · `modal` · `hostOverlay` · `checkbox-tree` · 可搜索 `select`

修改共享行为必须同步本模块调用方。共享组件本身由 Platform `@liveshops/design-tokens` 维护，不要在本模块复制一份。

## 8. 门禁与完成

| 级别 | 业务模块 | Gateway | Platform |
|---|---|---|---|
| Fast | `./business/backend/tools/verify-fast.ps1` | `./tools/verify.ps1` | `./backend/tools/verify.ps1` |
| Domain | `./business/backend/tools/verify-domain.ps1` | — | domain 五件套 |

开工前 domain 脚本必须通过。`cmd/archcheck` 按传递闭包强制分层，拦截 surface 互导和环境变量。

交付前：

1. Fast 在干净工作树上第一次通过。
2. 新 operation 在 Manifest、`g.Meta`、router 中间件、前端 `api.request`、`allowedRoutes` 五处一致。改完后按本仓库 [`docs/命名规范检查.md`](./命名规范检查.md) 评审。
3. 每个能力至少一条放行和一条拒绝（无凭证、缺权限、路由越权、surface 不符）。
4. 写入有幂等与版本冲突测试；涉及 SQL 的跑真实 MySQL。
5. 后台页过 UI 审计脚本。
6. 迁移语义对照：同一 `merchant_id + shop_id` 场景结果一致。
7. 改已发布 id/path 时升 major，并改全部调用方。

「完成」= 故障后不变量仍收敛，不是接口返回 200。
